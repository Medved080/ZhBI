# Панели облицовки шахт подъемников — отдельный комплект разработки

Назначение: импорт поштучных панелей ГП1/ГП2 в существующий объект **«Москвич», тип учета ЖБИ**. Это панели внутри здания, не фасадные панели и не новый объект МФР.

Текущий сервис не изменен. Весь новый код, тесты, результаты анализа и инструкция находятся в этой папке. Модули не подключены к `app.main`; миграции к файлам баз не применялись.

## С чего начать

1. Открыть [отчет распознавания](reports/report.html): выбор панели связывает развертку, пространственный вид и карточку. Файл работает без интернета; открывается двойным щелчком в обычном браузере.
2. Прочитать [фактический разбор DXF](DXF_FINDINGS.md).
3. Передать Claude Code [инструкцию внедрения](CLAUDE_CODE.md). В ее начале — готовый запрос, затем конкретные изменения и критерии приемки.
4. Архитектура, ограничения и этапы разработки: [DESIGN.md](DESIGN.md).

## Что реализовано

- Чтение DXF через уже установленный `ezdxf`, геометрические проверки через `shapely`.
- Профиль семейства чертежей ГП1/ГП2: разделение плана и разверток, контуры, марки, восемь сторон, отметки, извлечение осей из атрибутов блоков.
- Автоматическое совмещение с сеткой выбранного объекта по осям **5, 7, Е, Ж**, без растягивания и без угадывания глобального начала координат.
- Новый тип `Панель облицовки шахты`; марка изделия хранится отдельно (30 марок в исходном файле).
- Поштучные идентификаторы; одинаковая марка на разных сторонах/высотах не склеивает изделия.
- Предпросмотр → применение; проверка доступа, срока и владельца токена, повторная проверка данных, транзакция, защита существующих статусов и контрактов.
- Дополняющий импорт только собственной области ГП1/ГП2. Никакие чужие элементы не помечаются отсутствующими.
- ES-модуль формы импорта и функция правильной высоты для текущего Three.js-рендера.
- Ведомость CSV, подробный JSON, SVG разверток/модели и интерактивный HTML-отчет.

**Это комплект для внедрения, а не уже подключенная функция сервиса.** Обвязка текущих справочников, выбор нескольких текущих чертежей, защита обычного импорта от снятия актуальности панелей и подключение 3D требуют изменений, перечисленных в `CLAUDE_CODE.md`.

В тестах объемов **60 мм — только синтетический параметр**, не измеренная толщина изделий. В итоговом отчете толщина не задана: показаны лицевые поверхности. Толщина стенки 300 мм в плане не доказывает толщину одной облицовочной панели.

HTML собран из проверенного JSON, SVG проверяются отдельно; живая проверка HTML в браузере этой сессии не выполнена: политика браузера запретила открытие локального `file://`. Проверка мастера импорта в живом интерфейсе включена в приемку Claude Code.

## Команды из корня проекта

Никакие зависимости текущего проекта менять не нужно. Поддержаны Python 3.9+; серверный Docker использует Python 3.12. Новых сторонних библиотек и вендорного кода нет.

```bash
cd /Users/max/zhbi-tool
PYTHONPATH=. .venv/bin/python -m unittest discover -s feature_shaft_panels/tests -v
```

Восстановить отчет с координатами плана DXF:

```bash
.venv/bin/python -m app.shaft_panels \
  'Input/260908_ПП 5-7_Е-Ж.dxf' \
  --out feature_shaft_panels/reports/local-plan
```

Восстановить отчет с сеткой объекта из обезличенной копии (в проверенной копии нужная сетка у объекта №1; в другой базе ID нужно выбрать, не зашивать):

```bash
.venv/bin/python -m app.shaft_panels \
  'Input/260908_ПП 5-7_Е-Ж.dxf' \
  --db-readonly data/zhbi.anon.db --object-id 1 \
  --out feature_shaft_panels/reports
```

Повторить проверку совместимости с БД без изменения исходного файла:

```bash
.venv/bin/python \
  feature_shaft_panels/tests/check_database_copy.py \
  --db data/zhbi.anon.db --object-id 1 \
  --dxf 'Input/260908_ПП 5-7_Е-Ж.dxf' \
  --out feature_shaft_panels/reports/database-check.json
```

Можно передать `--axes-json path.json` вместо БД. Формат:

```json
{"numeric":{"5":10000,"7":19000},"letter":{"Е":20000,"Ж":32000}}
```

Координаты примера вымышленные. CLI читает БД через `mode=ro`; ничего в сервис не импортирует. Для отдельных файлов с тем же содержанием имя DXF несущественно.

## Состав

```text
shaft_panels/
  parser.py       распознавание и доказательства соответствий
  placement.py    развертка → план шахт → координаты объекта
  storage.py      миграция, анализ и транзакционный импорт в elements
  api.py          FastAPI router factory, защищенные токены
  report.py       HTML/SVG отчет
  __main__.py     CLI без записи в базу
integration/
  host_adapter.py  адаптер существующих ACL/backup/зон/обновления
  shaft-panels.js  мастер импорта и высота 3D-экструзии
  protect_standard_import.py  готовые функции изоляции обычного DXF-импорта
  architecture-map.json      AST-карта точек интеграции
  type-usage.json            найденные места обработки типов
 tests/           воспроизводимые проверки
 reports/         результат на исходном DXF
```

Отчеты содержат реальную геометрию исходного чертежа. Они не отправлялись во внешние приложения; в корпоративный контур передавайте комплект обычным принятым способом.
