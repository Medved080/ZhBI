## Что это

ЖБИ-трекер: веб-инструмент для отслеживания статусов поставки/монтажа
сборных железобетонных элементов на стройплощадке. Чертежи — DXF,
загружаются через UI или кладутся в `Input/` (подхватываются при
старте сервера). Данные — марка, тип, координаты, адрес по осям,
привязка к зонам (захватка/кран/стоянка), статус, контракт, история.

## Стек и структура

- **Backend**: FastAPI + Starlette (синхронные `def`-роуты, threadpool),
  SQLite без WAL (`app/db.py`). Сессии — cookie, 30 дней. Три роли
  пользователей.
- **Frontend**: один файл `app/static/index.html` (~4000+ строк) —
  vanilla JS + SVG для 2D-схемы, Three.js (вендорено локально,
  `app/static/vendor/three/`, НЕ CDN — см. "Ключевые решения" ниже) для
  3D-режима. Никакого сборщика/фреймворка.
- **Импорт DXF** — два параллельных конвейера, старый не трогать при
  правке нового:
  - Старый (`scripts/parse_zhbi.py`, `LAYER_CONFIG`) — плоские слои без
    зон/подтипов/отметок.
  - Новый стандарт имён (`scripts/layer_naming.py`,
    `scripts/new_standard_pipeline.py`) — слои `WEB_констр_...` /
    `WEB_тех_...`, с зонами, подтипами, отметками. Только новый
    конвейер поддерживает зоны и 3D.
  - Адресация по осям — `scripts/assign_axes.py` (общая для обоих).
  - Зоны (захватка/кран/стоянка) — `scripts/zone_parser.py` (реестр,
    сопоставление названий, связь стоянка→кран) +
    `scripts/zone_binding.py` (привязка элемента к зоне).
  - Оркестрация загрузки через UI — `app/dxf_import.py` (сохранить →
    распарсить → адресовать → записать), переиспользует те же функции,
    что и CLI-скрипты `scripts/*.py`.
- **Тесты/проверка** — нет pytest-сюиты; методология: изолированные
  Python/Node-скрипты в `/tmp`, тестирующие извлечённые функции на
  РЕАЛЬНЫХ данных из `data/zhbi.db` (`plan_data()`/прямые SQL-запросы),
  плюс один сквозной синтетический тест `scripts/verify_zone_pipeline.py`
  (`test_data/synthetic_zones.dxf`, генерится
  `scripts/generate_test_zones_dxf.py`). Живого браузерного тестирования
  нет (нет инструмента автоматизации браузера в этой среде) — это
  открытый пробел, проговаривается пользователю после каждого раунда UI-
  правок.

## Ключевые решения (коротко, детали — в Docs/backlog.md по дате)

- **Единый русский словарь `element_type`** — Колонна/Ригель/Плита/
  Панель, миграция идемпотентна (`app/db._normalize_element_type_vocabulary`).
- **Фильтры на клиенте** (`app/static/index.html`) — архитектура "полный
  список значений всегда виден + недоступен (disabled), не сужается" —
  фикс двух багов самоблокировки. `PLACEMENT_CASCADE_GROUPS` = пары
  [`elementType`,`subtype`] и [`crane`,`stance`] — при расчёте
  доступности одной категории пары фильтр ДРУГОЙ игнорируется.
  Иерархические группы (`buildHierarchicalFilterGroup`) сворачиваемы
  (по умолчанию закрыты, кроме родителя); клик по потомку, если родитель
  сейчас выключен, включает и родителя (но не остальных потомков) —
  иначе включить одну стоянку при выключенном кране было невозможно.
- **Стоянка крана ≠ точка** — рабочая зона крана в конкретной позиции.
  Элемент без конкретной стоянки, но с известным краном — псевдо-значение
  `no-stance:<craneId>` (метка "вне стоянок"), ложится ДОЧЕРНИМ пунктом
  под свой кран, не в общий "не определено".
- **Лесенка сужения зоны стоянки с высотой** (главная фича последнего
  раунда, см. ниже) — на каждом ярусе колонн ближний к крану край окна
  стоянки отступает на 1 реальный пролёт сетки осей, следующая по номеру
  стоянка подхватывает уступленное. `scripts/zone_binding.
  build_stance_level_polygons` + `compute_column_tier_elevations`.
- **Цвета зон по крану** — `zone_colors` таблица ключуется
  `(source_file, category, name)`, НЕ `zones.id` (нестабилен между
  переимпортами — `upsert_zones` делает DELETE+INSERT каждый раз).
- **3D-режим** — Three.js 0.160.0, вендорено ЛОКАЛЬНО. Перед вендорингом
  стороннего кода ОБЯЗАТЕЛЬНО явное подтверждение пользователя — уже
  было получено ("подтверждаю"), но при любом НОВОМ стороннем коде
  правило действует снова. Координатное отображение: `world.X=dxf.x`,
  `world.Z=-dxf.y` (внимательно с знаком — уже был баг зеркальности).
  `OrbitControls.zoomSpeed=4` (дефолт 1 слишком медленный для трекпада).
- **Docs/TZ.md обновляется на КАЖДОЕ функциональное изменение** без
  напоминания — стоячая инструкция, отдельно от этого файла.
