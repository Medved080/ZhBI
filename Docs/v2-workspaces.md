# Рабочие места со схемой в V2

Ветка `feature/v2-workspaces` (от `main` `0c6aba6`, ограниченный выпуск V1 + экспериментальный V2). Не слита, не запушена,
не развёрнута. V1 остаётся самостоятельным: его файлы менялись только режимом кадра (см. ниже), обычный запуск V1 их не задевает.

Что сделано: четыре РАБОЧИХ места внутри V2 — с настоящей схемой выбранного объекта, а не страницы-заглушки:
«Модель: схема 2D/3D» (ЖБИ), «Модель МФР», «АРМ комплектовщика», «АРМ прораба». Открываются из левой навигации V2
(`/v2#/ws-model`, `#/ws-mfr`, `#/ws-picker`, `#/ws-foreman`), объект берётся из шапки V2.

## 1. Как устроено

Схему рисует движок V1 (`app/static/app.js`, ~36 тыс. строк: SVG 2D, Three.js 3D, выбор, координаты, семантика). Он завязан на
глобальный DOM документа V1, поэтому его нельзя вынуть, не переписывая, — а переписывать его задание запрещает. Поэтому:

* **Сцена в кадре.** V2 создаёт `<iframe>` с документом V1 в специальном режиме «только сцена» (`EMBED_SCENE` в начале `app.js`,
  стили `embed-scene.css`): шапки, меню, боковых панелей, строки состояния и панелей рабочих мест V1 в кадре нет — они скрыты
  и не управляют ничем. В кадре остаётся холст схемы (2D/3D), его жесты (колесо — масштаб, перетаскивание — сдвиг, клик —
  выбор, Shift + рамка — групповой выбор) и подсветка выбранного.
* **Всё остальное — в V2** (`app/static/v2/workspace.js`): компактная верхняя панель (режим 2D/3D, поиск), инструменты рядом со
  сценой (вписать, приблизить, отдалить, снять выбор), правая панель (свойства / статус / фильтры / вид), строка состояния
  (показано, выбрано, ограничения, режим), сворачиваемая глобальная навигация и правая панель, ширина панели — мышью и стрелками.
* **Кадр строится из `srcdoc`, а не по адресу.** Сервер запрещает показ своих страниц в кадрах (`X-Frame-Options: DENY`,
  `frame-ancestors 'none'` — `app/main.py`, `security_headers`). Заголовки НЕ менялись (backend по заданию не трогаем):
  V2 читает страницу `/` обычным GET и кладёт её в `srcdoc` кадра (тот же origin, та же CSP, `<base href="/">`). Параметры режима
  (объект, рабочее место) передаются атрибутом `data-zhbi-scene` самого `<iframe>` — `app.js` читает их через `frameElement`.
  Если позже заголовок будет ослаблен до `frame-ancestors 'self'`, можно перейти на обычный адрес `/?embed=scene` — движок
  понимает оба способа. (Это единственное место, где нужна отдельная просьба к владельцу backend; без неё всё работает.)
* **Единый источник состояния.** Объект — в шапке V2 (`main.js`): смена объекта → команда `setObject` тому же кадру (V1 сам сбрасывает
  выбор и фильтры прежнего объекта, запоздавшие смены схлопываются до последней) либо переход на парное рабочее место при смене
  типа учёта (ЖБИ ↔ МФР). Выбор, фильтры и режим 2D/3D живут в движке (это его модель) — V2 отображает их снимком и меняет командами,
  своей копии не ведёт. Права на смену статуса — от `/me/permissions?object_id=`.
* **Уход с экрана.** Кадр обнуляется и удаляется (вместе с документом уходят WebGL-контексты, таймеры и слушатели), слушатель
  сообщений снимается, навигация возвращается в прежнее состояние. Проверено: 8 циклов «вход → 3D → выход» — кадр один/ноль, слушатель
  один/ноль, память возвращается к исходной (25 → 30 МБ после выхода), предупреждений о лишних WebGL-контекстах нет.

## 2. Канал «кадр ↔ V2» — протокол `zhbi-scene/1`

Только `postMessage` между кадром и его родителем; обе стороны проверяют `e.source` (только «свой» кадр / «свой» родитель),
`e.origin` и поле `proto`, всё остальное молча игнорируют. HTML и код не передаются: кадр → V2 — числа, строки, даты (карточка
выбранного берётся из ФИКСИРОВАННОГО списка полей); V2 → кадр — команды из белого списка с проверкой типов и границ.

| Направление | Сообщение |
| --- | --- |
| кадр → V2 | `ready`, `state` (снимок: объект, режим, загрузка, ошибка, счётчики, выбор), `filters` (модель фильтров ЖБИ), `picker` (срезы/показатели/контракты), `search-result`, `refreshed`, `notice`, `cmd-error` |
| V2 → кадр (ЖБИ) | `setObject`, `setView{2d\|3d\|3d-light}`, `fit`, `zoom{factor}`, `select{id\|null}`, `locate{id}`, `clearSelection`, `setFilter{changes}`, `resetFilters`, `setZoneVisible`, `search{text}`, `refreshElement{id}`, `getFilters`, `reload` |
| V2 → кадр (МФР) | `mfrPick{kind,id}`, `mfrCategory{category,on}`, `mfrLayer{layer,on}`, `mfrReset`, `mfrSelect{kind,id,additive}` (+ общие `setView{2d\|3d}`, `fit`, `zoom`, `clearSelection`) |
| V2 → кадр (комплектовщик) | `pickerToggle{key,value}`, `pickerSet{key,values,on}`, `pickerClear{key}`, `pickerMetric{key,on}`, `pickerHighlight{on}` |

Реализация: `app/static/embed-bridge.js` (классический скрипт кадра: вызывает функции движка, а не копирует его логику).
Отбор и выбор считают сами обработчики V1 (`onPlacementFilterChange`, `pickerElementPasses`, клики по `.revit-pick` и т.д.) —
поэтому числа и состав схемы совпадают с V1.

## 3. Защита данных

* **Кадр работает только на чтение.** В режиме кадра `window.fetch` отсекает любой запрос, кроме GET/HEAD и чтения геометрии
  `POST /plan-data`, ещё ДО сети (ответ 403 «в окне схемы запись отключена»; журнал действий `POST /activity` — тихий 204;
  `sendBeacon` отключён). Значит, контекстное меню сцены, двойной клик, горячие клавиши, групповые действия, диалоги V1 и прямые вызовы
  старых обработчиков не могут ничего записать. Проверено на настоящем backend: `POST/PATCH/DELETE/PUT` из кадра → 403 без обращения к серверу.
* **Запись — только оболочка V2 через шлюз** (`write-gate.js`, запрет по умолчанию; шлюз НЕ ослаблялся). Единственная запись рабочих мест —
  **смена статуса ОДНОГО элемента** (`PATCH /elements/{id}/status`), добавлена в таблицу политики строкой `element.status` (теперь 21
  разрешённая операция; `Docs/v2-write-policy.md` пересобран). В теле разрешены только `status`, `changed_at`, `comment`: контракт не
  передаётся (со `contract_id` шлюз отказывает), массовая смена статусов, смена контракта, плановой даты, история, поля элемента — отключены.
* Форма («Свойства» выбранного элемента ЖБИ) показывается только при праве «статусы: изменение» на объекте; запрос идёт на ID
  выбранного элемента; на время записи форма заблокирована, повторная отправка невозможна (двойной клик — один запрос); при отказе
  сервера текст показан, введённое осталось; при сетевом сбое/5xx исход считается НЕИЗВЕСТНЫМ: автоповтора нет, элемент перечитывается
  и говорится, что видит сервер; после успеха схема обновляется тем, что подтвердил сервер (`refreshElement` — GET элемента и штатное
  точечное обновление V1), история перечитывается. Несохранённый ввод при уходе — сторож «Остаться / Не сохранять / Сохранить и продолжить».
* Недоступность записи не мешает просмотру, фильтрам и выбору.

## 4. Что работает

| Рабочее место | На чтение и в интерфейсе | Запись |
| --- | --- | --- |
| Модель: схема 2D/3D (`ws-model`) | реальная схема объекта в 2D, 3D и 3D лёгком; масштаб колесом, сдвиг, «вписать», ± ; выбор элемента → карточка (размещение, контракт, даты, история статусов с сервера); множественный выбор (сводка); поиск по марке/адресу; фильтры (захватка, кран/стоянка, этаж, отметка, тип/подтип/марка, статус, контрагент/контракт, «без контракта») со счётчиками и сбросом; статусы; слои зон | смена статуса одного элемента |
| АРМ прораба (`ws-foreman`) | та же схема; отбор постоянной панелью слева; полоса показателей (число элементов, доля смонтированных и принятых, статусы) | смена статуса одного элемента |
| АРМ комплектовщика (`ws-picker`) | схема с собственным отбором: срезы (тип, подтип, марка, захватка, кран, стоянка, этаж) с колонками «модель / контракт / Δ»; плитки показателей (в модели, запланировано, законтрактовано, без контракта, с плановой датой, доставлено, смонтировано) — кросс-фильтр; контракты по контрагентам: всего / привязано / остаток, выбор, «без контракта», подсветка несвязанных, «только с остатком» | смена статуса одного элемента |
| Модель МФР (`ws-mfr`) | план по этажам (2D) и модель (3D) из выгрузки Revit; отбор по этажам, секциям, категориям; слои (элементы, блоки, оси, фасады, планы); выбор блока или элемента → карточка (для блока — состав, габарит, виды работ; для элемента — свойства и параметры Revit) | нет |

## 5. Ограничения (что НЕ перенесено)

* Записи на МФР, у комплектовщика и прораба, кроме смены статуса одного элемента ЖБИ: контракты и привязка позиций, массовая смена,
  плановые даты, комментарии, факт/настройки/сроки работ блока — в текущем интерфейсе (форма показывает это текстом).
* МФР: не перенесены отборы по видам работ / статусу выполнения / сроку / периоду, «Динамика за период» и раскраска «Шахматка»
  (остаются в V1); показ элемента на плане («Показать на схеме») для МФР не поддержан.
* Комплектовщик: не перенесены развороты контракта по маркам и связь позиций с элементами; прораб — поиск только по марке/адресу.
* Кадр по-прежнему выполняет весь фоновый запуск V1 (несколько лишних GET при входе: права, справочники, опрос изменений) — время
  входа сопоставимо с V1 (на объекте 9580 элементов: V2 ≈ 6 с, V1 ≈ 10 с от начала навигации в свёрнутой панели браузера; без
  сверки в видимом окне цифры ориентировочные).
* Заголовки `X-Frame-Options`/`frame-ancestors` не менялись (см. §1); переход на кадр по адресу возможен только по решению владельца backend.
* Скриншоты в файлы из встроенной панели браузера сохранить нельзя (инструмент возвращает изображение только в ответе) — при приёмке
  смотрите рабочие места по ссылкам из отчёта.

## 6. Проверка

Живая — на настоящем backend (`uvicorn`, свободный порт, обезличенная копия БД `data/zhbi.anon.db`, объекты 1 — 9580 элементов ЖБИ,
2 — 4926, 3 и 4 — модели МФР на 30078 и 11308 элементов), встроенный браузер:

1. ЖБИ: схема загружена (геометрия видна), клик по элементу → карточка + история; колесо → масштаб (100 → 115 %); фильтр «Статус →
   Контрактация» снимает 2 из 4926 (счётчик 4924); 2D → 3D → 3D лёгкий; смена объекта 2 → 1 → МФР → ЖБИ без перезагрузки страницы;
   8 циклов входа/выхода без накопления слушателей и кадров.
2. Кадр только читает: POST/PATCH/DELETE/PUT из кадра → 403 (без сети); неизвестные команды, неверные параметры, чужие сообщения — отбраковка.
3. Смена статуса элемента 40558 (объект 2): «Запланирован» → «Контрактация» → «В производстве»; в БД ровно по одной записи истории на каждое
   подтверждённое сохранение, `contract_id` не тронут; имитация обрыва сети — один запрос, ввод сохранён, исход проверен чтением, ручной
   повтор — один запрос; двойная отправка — один запрос.
4. МФР (объект 4, 11308): план блоков, фильтр «3 этаж» → 642 элемента / 2 блока, клик по блоку → карточка (С01 · Этаж 3, 293 элемента,
   29272×16406×3000 мм, работы: план 5), слои, 3D с подсветкой выбранного блока; объект 3 (30078 элементов) — загружается.
5. Комплектовщик (объект 1): срез «Колонна» → 1328 из 9580, «законтрактовано 751, дефицит 577», Δ −577; плитки и контракты
   (остаток) считаются теми же функциями, что панель V1.
6. Прораб: полоса показателей (3 % смонтировано и принято), поиск «П» → 30 результатов, панель отбора слева.
7. V1: `/?ui=v1&object_id=1&ws=picker` — рабочее место V1 открывается, ни `embed-*` файлы, ни кадр не запрашиваются.

Автоматически (стенд без геометрии, `scripts/v2_test_server.py`, наборы в `scripts/v2_tests/`): новый набор `ws` — 10 сценариев
(`WS-01…WS-10`: кадр из srcdoc и геометрия на 1920×1080, 1920×900, 1366×768 без прокрутки страницы; выбор ↔ панель и запоздавший
ответ; отбраковка чужих/неверных сообщений и белый список команд; фильтры; ошибка/пустота/повтор; смена объекта и переход ЖБИ↔МФР; уход
без накопления слушателей; смена статуса — отказ, сетевой сбой, двойная отправка, тело запроса, шлюз; сторож ухода; панели прораба и
комплектовщика). В кадр подставляется заглушка с тем же протоколом — настоящий движок и геометрия проверяются живой проверкой выше.
Полный прогон стенда: 377 PASS / 15 FAIL / 77 «отключено шлюзом» из 469; 15 FAIL — карта MapLibre в безголовом Chrome (VIS-po-*, VIS-dialog-confirm-danger),
идентично падают на базовом коммите `0c6aba6` (не регрессия; в обычном браузере проходят).

## 7. Как посмотреть (короткий маршрут)

1. Запустить сервер на копии БД (не 8000/8010/8020): `ZHBI_DB_PATH=data/zhbi.anon.db .venv/bin/python -c "import uvicorn; uvicorn.run('app.main:app', host='127.0.0.1', port=8071)"`
   из каталога `.claude/worktrees/v2-workspaces`, войти (вход делает человек).
2. Открыть `http://127.0.0.1:8071/v2?object_id=1#/ws-model` → схема → щёлкнуть по элементу (справа карточка) → вкладка «Фильтры» → снять
   значение (счётчик «Показано» уменьшится) → «Сбросить все» → 3D. Тем же путём — `#/ws-foreman`, `#/ws-picker`; для МФР выберите в шапке объект
   с моделью Revit (3 или 4) → `#/ws-mfr`.

## 8. Точка продолжения

Не сделано (по убыванию значимости): записи на МФР/комплектовщике (привязка контракта, массовая смена — каждая только после проверки и внесения в
политику шлюза); отборы МФР по видам работ/срокам, «Шахматка»; проверка в видимом окне времени входа и отзывчивости на 30-тысячном объекте;
скриншоты для приёмки (нужен видимый браузер с сохранением файлов).
