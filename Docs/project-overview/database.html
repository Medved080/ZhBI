Устройство хранилища

Основная база

Файл SQLite в режиме WAL: все данные трекера. Миграции схемы выполняются при старте, перед обработками данных снимается копия.

Адресный классификатор

Отдельный файл КЛАДР: подсказки по населённым пунктам и улицам. Не входит в основную базу, чтобы не раздувать копии.

База калькулятора

Отдельный файл подсистемы расчёта: изделия, версии расчётов, нормы, прайс-лист, чтение чертежей, очередь синхронизации. Своя схема и миграции.

Ключевые связи

Четыре главные оси данных: иерархия (проект → объект), изделие (объект → элементы → история статусов), юридическая цепочка (контрагент → договор → спецификация → контракт → позиции) и время (версии графика). Договор заключается на объект, контракт ссылается на спецификацию, изделие — на контракт и зоны.

Правила, общие для всей схемы

  • Идентификаторы. Целочисленные id; объект дополнительно имеет сквозной object_uid для обмена между серверами, изделие — element_uid.
  • Каскады. Дочерние записи объекта удаляются вместе с ним (CASCADE); записи, на которые ссылаются справочники, защищены от удаления (RESTRICT) — вместо этого их переводят на замену.
  • Авторство. Сущности хранят ссылку на пользователя (SET NULL) и текстовый снимок ФИО, чтобы история переживала удаление учётной записи.
  • История не перезаписывается. Статусы, версии графика, редакции кранов, версии прогноза ЗР — накапливаются записями.
  • Описание схемы одно. Назначение каждой таблицы и поля хранится в одном модуле и сверяется с реальной базой: расхождение подсвечивается в интерфейсе администратора.
  • Логические связи без внешнего ключа (например, привязка изделия к версии чертежа по имени файла) перечислены в описании схемы отдельно.
