# V2: стабилизация и приёмка — матрица

Единый документ этапа «закрытая стабилизация и приёмка существующего V2»
(три раздела: Пользователи и доступ, Проекты и объекты, Контрагенты).
Заведён 2026-09-20 на коммите `c0b156e`, ветка `worktree-v2-overnight-migration`.
Статус этапа: **В РАБОТЕ**.

## 0. Среда, правила, уровни доказательств

- Каталог: `/Users/max/zhbi-tool/.claude/worktrees/v2-overnight-migration`.
  Сервер приёмки: `http://127.0.0.1:8021`, процесс запущен из этого
  каталога на `data/zhbi.anon.db` (сверяется `lsof -p <pid>` перед каждым
  браузерным прогоном; порт сам по себе ничего не доказывает).
  Рабочая БД, порт 8000 и чужие процессы не затрагиваются.
- Изменяющие сценарии — только на синтетических записях с префиксом
  `QA-ACC-` в анонимной копии; чужие записи и права реальных пользователей
  не меняются; созданное удаляется и удаление подтверждается SQL.
- Пароли не вводятся мной ни в какие поля (запрет среды). Вход в реальный
  сервер выполняет пользователь; сценарии, где требуется ввод пароля,
  проверяются только на фейковом бэкенде (уровень H) и помечены отдельно.
- **Уровни доказательств:**
  - **T** — автотест без браузера (`node scripts/verify_v2_*.mjs`);
  - **H** — сценарий в браузере на стенде без входа и без БД: настоящие
    модули V2 + фейковый бэкенд (`scripts/v2_test_server.py`,
    `scripts/v2_tests/`), где ошибки 403/409/422/500, сетевой сбой и
    задержки моделируются, а каждый отправленный запрос журналируется;
  - **L** — живой сервер 8021 на анонимной БД (реальный бэкенд, права,
    SQL-подтверждение);
  - **К** — чтение кода. Не засчитывается как «пройден» никогда.
- Сценарий получает **«пройден»** только когда выполнены ВСЕ уровни,
  перечисленные в столбце «Способ». Статусы: не проверен / ошибка / пройден /
  заблокирован. «Неприменимо» не используется вместо отсутствующего теста.
- Финальный прогон обязателен после последнего изменения затронутого кода;
  любая правка кода аннулирует приёмку затронутых строк (они возвращаются в
  «не проверен» с пометкой ревизии).

## 1. Фиксированный объём этапа

**В объёме:** все формы, вкладки, диалоги и операции трёх разделов V2
(перечислены в разделе 2), оболочка (`main.js`, `login.js`, `dialogs.js`,
`api.js`, `icons.js`, `styles.css`), переход V1↔V2, известные дефекты (раздел 3),
регрессия плановых дат и взаимной блокировки операций контракта, визуальная
приёмка на 1920×1080, 1920×900, 1366×768 (масштаб 100%), клавиатура и фокус.

**Вне объёма (не реализуется, только фиксируется в разделе 4):** новые
справочники (СМУ, физлица, типы/подтипы, марки), любые новые функции,
перенос функций, сознательно оставленных в V1 (диагностика домена, сеансы,
«войти от имени», полный редактор контракта в карточке объекта), изменения
backend, схемы БД, прав и бизнес-правил, темы V1 кроме светлой/тёмной семьи.

## 4. Вне объёма (пожелания и замечания к V1/backend, не реализуются)

- Серверные замечания: `POST /marks`, `POST /allowed-subtypes`,
  `GET /allowed-subtypes` не проверяют доступ пользователя к объекту;
  `POST /mark-type-prefixes` не валидирует `element_type`; сырые `DELETE`
  подтипов/префиксов в обход `dict_delete`.
- V1: корзина справочников показывается без проверки `dict_delete`; ошибки
  через `alert()`; модалка подтипов не ловит 403 на `/marks`.
- Отдельный редактор типов изделий (типов как справочника нет).
- Перенос диагностики домена, сеансов, «войти от имени», полного редактора
  контракта объекта; добровольная смена пароля из меню в V2.
- Размеры `.v2-dialog` (420) и `.v2-auth-card` (340) против стандарта small 480 —
  решение по дизайну, не дефект функциональности.
