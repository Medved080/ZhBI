## 3. Сервер: отдавать всё здание и наружный контур

`app/object_geometry_features.py`:

1. Отбор уровней и отрезков не должен терять ни одной части здания.
   Критерий выбора уровней — разнообразие плана (уровни с разным
   контуром в плане обязаны попасть в выборку), а не только периметр.
   Потолки по числу отрезков сохранить, но добиваться их за счёт длины
   рёбер внутри уровня, не за счёт целых уровней. Ключ группировки
   отметок — не 10 мм: два перекрытия одного этажа на 163.6 и 163.7 м —
   один уровень.
2. Добавить в ответ наружный контур: объединение контуров перекрытий
   (`category='Перекрытия'`, у объекта 3 все 1 309 с `outline_json`) по
   уровню → внешние кольца, с сохранением вогнутостей и разрывов;
   формат ответа — `walls` (как сейчас `segments`, для обратной
   совместимости оставить и старое имя) плюс `envelope:
   [{z0, z1, rings: [[[x, y], ...]]}]`. Прототип растеризации из прошлой
   сессии не сохранился — реализовать заново; полигональное объединение
   собственным кодом или растеризацией на numpy (уже в зависимостях).
   Новых пакетов не добавлять без подтверждения пользователя.
3. Скрипт-страж `scripts/verify_geometry_features.py`: для каждого объекта
   с моделью МФР сравнивает габарит отдаваемого набора с габаритом полного
   набора стен по каждой секции и по каждому направлению-пику; расхождение
   больше 300 мм — FAIL. На объекте 3 копии до правки он обязан падать
   (17.6 против 36.4), после — проходить.

## 4. Клиент: сопоставлять части, а не агрегаты

`app/static/external-models/auto-align.js`, `settings.js`:

1. `checkSizeCompatibility` — только по парам частей. Правило: каждая
   значимая часть объекта должна найти часть FBX с совместимым габаритом
   (допуск — облицовка + погрешность, как сейчас, с объяснением в
   комментарии). Части FBX без соответствия в объекте (соседнее здание,
   благоустройство, кровельные детали) — не ошибка, а «область вне
   применимости»: они исключаются из ICP и оценки, и об этом сообщается.
   `hardFail` — только когда НИ ОДНА часть объекта не имеет совместимой
   части FBX.
2. Поворот не терять никогда. Если перенос не подтверждён, результат —
   `low_confidence` с найденным углом (из пиков направлений и ICP) и
   явной причиной, а не `insufficient_geometry` с пустым списком.
   `insufficient_geometry` — только когда нет стен или нет пиков.
3. Цель сопоставления — `envelope` объекта (наружный контур), стены —
   только если контура нет; направленное сопоставление: точка FBX
   соответствует только отрезку, чья нормаль совместима с нормалью
   грани FBX (нормаль есть в `extractWallSegmentsFromGroup`, сохранить её
   в сегменте). Внутренняя стена с этого момента не должна быть целью.
4. Двусторонняя оценка по сторонам и частям: FBX→контур и контур→FBX,
   отдельно по каждой стороне каждой части; метрика выступания —
   характерная и максимальная глубина выхода контура конструктива за
   оболочку FBX по каждой стороне, с допуском на облицовку/балконы.
   Кандидат, у которого выступание на какой-либо стороне больше допуска,
   не проходит, каким бы ни был сводный coverage. `ambiguous` — только
   если прошли несколько.
5. Диагностика — на карточке модели (в `auto_placement_json`, показывать
   постоянно, как сейчас причину): габариты частей FBX и объекта,
   какие части сопоставлены, выступание по сторонам, угол/сдвиг. Плюс
   ортографический план-наложение (небольшой SVG на карточке: контур
   объекта, контур FBX в найденном положении, части и стороны с
   превышением выделены). Это диагностика для человека, на логику не
   влияет.

Не делать: не увеличивать число итераций, не ослаблять пороги, чтобы
проверка «прошла», не масштабировать и не деформировать ни один набор,
не менять Z автоматикой.
