# Аудит интерфейса калькулятора ЖБИ

Дата: 05.10.2026. Основание: приложенный скриншот и текущий код подсистемы `app/calc/web`, включая её встраивание в V2. Основной сценарий подтверждён пользователем: **найти изделие и работать с его калькуляцией**.

Главная проблема — распределение пространства и смешение уровней управления. Постоянная левая панель объединяет каталог, навигацию, прогресс 3D, обработку, экспорт, отчёт и передачу на серверы. Каталог получает остаток высоты. Первым открывается большой отчёт о готовности, хотя для основной задачи нужны список изделий и карточка расчёта.

Предлагаемое направление: стартовый экран «Изделия», самостоятельная панель каталога, компактная карточка справа и отдельные разделы для готовности, цен и отчётов. Переработка должна прежде всего вернуть место основному сценарию.

Дополнительное указание пользователя: блок «3D по всей базе» в левой панели не нужен, поскольку эти данные уже есть на дашборде главной страницы калькулятора. В проекте переработки этот блок полностью исключён из каталога; ссылка на результаты обработки переходит в «Сервис».

## Границы аудита

Выполнен экспертный разбор скриншота и реализации. Это не исследование поведения пользователей и не проверка всех экранов на работающем сервере. Оценки удобства — экспертные выводы; утверждения о реализации ниже привязаны к исходникам. Числа 1 008, 28,7%, 552 и 26 из 54 относятся к снимку пользователя, а не к актуальному состоянию базы.

Рабочий интерфейс, серверная логика и база данных в рамках подготовки не меняются. [Макет](mockup.html) показывает предложенную структуру на демонстрационных изделиях и ценах. [Задание на переработку](DESIGN.md) определяет поведение и критерии приёмки.

## Что уже стоит сохранить

Поиск учитывает марку и алиас, игнорирует пробелы и регистр. Есть группировка по альбомам и типам, а найденные группы раскрываются при поиске. Поддержаны независимое выделение, выгрузка нескольких изделий, исходные листы, история и сравнение своей калькуляции с расчётом сервиса.

В интерфейсе уже есть состояния сохранения, повтор при ошибке, локальные черновики, конфликт версий и режим просмотра. Эти возможности должны остаться видимыми и работать после перестановки элементов. Семь существующих цветовых гамм и общая оболочка V2 также сохраняются.

## Новая информационная структура

| Уровень | Содержание | Правило размещения |
|---|---|---|
| Общая оболочка ЖБИ | Проект, пользователь, переходы в другие подсистемы | Существующая шапка и внешняя навигация; не дублировать в каталоге |
| Калькулятор | Изделия, Готовность, Цены и нормы, Отчёты | Одна горизонтальная навигация под шапкой |
| Каталог | Поиск, альбом/тип, дополнительные фильтры, строки изделий | Левая панель только на экране «Изделия» |
| Активное изделие | Марка, краткий контекст, сохранение, XLSX изделия | Шапка правой рабочей области |
| Работа с изделием | Калькуляция, Модель, Документы, Проверка | Основные вкладки карточки |
| Редкие разделы изделия | Технология, История | Меню «Ещё» рядом с вкладками |
| Массовые действия | Выбрать найденные, снять выделение, XLSX выбранных | Нижняя строка каталога, с явным количеством и областью действия |
| Служебные операции | Обработка данных, результаты обработки, передача на серверы | Меню «Сервис» в навигации калькулятора, с существующей проверкой прав |

«Документы» объединяет исходные листы, приложенные файлы и основания расчёта, но сохраняет каждый самостоятельный подраздел. «Проверка» объединяет технические вопросы и коллизии в два подписанных подраздела. Наличие этого раздела не означает, что уже реализовано подтверждение человеком.

## Основные сценарии после переработки

1. **Найти и рассчитать.** Открыть калькулятор → увидеть каталог и последнее изделие → ввести марку → открыть строку → работать с калькуляцией. Для начала поиска не нужен переход через готовность.
2. **Уточнить данные.** Из калькуляции открыть параметр или сообщение о пробеле → перейти в соответствующий подраздел → вернуться к расчёту с сохранёнными фильтрами каталога.
3. **Выгрузить текущее изделие.** Нажать «XLSX изделия» в карточке. Действие явно относится к открытой марке и не меняет массовое выделение.
4. **Выгрузить несколько.** Отметить строки или «Выбрать найденные» → увидеть N выбранных, включая число вне фильтра → нажать «XLSX выбранных · N». Фильтр не снимает выделение молча.
5. **Исправить расценки.** Открыть «Цены и нормы» → найти материал/включить «Без цены» → изменить → сохранить. При возврате открываются прежнее изделие и каталог. Видимая подпись объясняет пересчёт всей базы.
6. **Контролировать проект.** Открыть «Готовность» → выбрать доступное действие по дефициту → перейти к нужному списку или ценам. Подробная воронка и сведения о происхождении остаются доступными по раскрытию.

## Визуальные правила

Рабочая область — спокойный фон, один основной синий акцент в каждой области действий и разделение тонкими линиями. Обводка нужна интерактивным полям и действительно самостоятельным блокам; вложенные карточки внутри карточек не должны быть основным способом группировки. Высоту списка увеличиваем переносом содержимого, сохраняя читаемый шрифт.

Размер основного текста — 14 px, вторичных подписей — 12–13 px, заголовка изделия — 20–24 px. Это проектные значения для плотного рабочего интерфейса, которые надо проверить с масштабом 125% и 200%. Мутный текст не должен скрывать существенные ограничения расчёта.

Статусы выражаются словами: «Предварительный расчёт», «Нет цены», «Нет данных», «Сохранено», «Ошибка сохранения». Цвет дополняет текст. Статус модели «Частичная 3D» не заменяет статус расчёта.

Для контраста обычного текста ориентир — не менее 4,5:1, для крупного — 3:1 согласно [WCAG 2.2, Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Нельзя объявить соответствие всему WCAG по одному скриншоту или одному макету.

Элементы управления должны иметь цель не менее 24×24 CSS px либо соответствовать исключениям по размеру/интервалам [WCAG 2.2, Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Для проекта выбираем удобнее: обычные кнопки высотой 32–36 px, сенсорные цели 44 px. Вкладки реализуются с ролями и клавиатурным управлением по [WAI ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/).

## Очерёдность изменений

| Этап | Что меняется | Результат |
|---|---|---|
| 1 | Стартовый экран, навигация калькулятора, очищенный каталог, высота списка | Основной сценарий получает пространство; перестают конкурировать каталожные и служебные элементы |
| 2 | Шапка изделия, группировка вкладок, XLSX изделия и массовый экспорт, компактная калькуляция | Область действия каждой кнопки понятна; расчёт удобен на ноутбуке |
| 3 | Компактная готовность, доступные переходы из дефицитов, ясные статусы | Сводка помогает перейти к действию и объясняет ограничения данных |
| 4 | Восстановление контекста, клавиатура, малые экраны, все темы, ошибки и права | Стабильная повседневная работа после переработки |

Подтверждение норм по группам и проверка человеком требуют самостоятельной серверной реализации. Их нельзя обещать как результат одной перестановки интерфейса. Новые фильтры по готовности также требуют данных на уровне изделия: текущий `/calc/api/readiness` отдаёт агрегаты.

## Как проверять результат

Предлагаемые цели для рабочего приложения: на 1366×768 список занимает не меньше 55% высоты области калькулятора и показывает минимум 12 строк при раскрытой группе; на 1920×1080 — минимум 18. Поиск доступен сразу, калькуляция открывается одним выбором строки. Конкретные размеры и сценарии приёмки перечислены в [DESIGN.md](DESIGN.md).

После реализации провести короткую проверку с пользователем на реальных задачах: найти изделие по марке и алиасу, исправить одну строку расчёта, открыть исходный лист, выгрузить одно и несколько изделий, вернуться после изменения расценки. Замерять время выполнения, лишние переходы и ошибки выбора области выгрузки. Цели — гипотезы для проверки, а не уже доказанное ускорение.
