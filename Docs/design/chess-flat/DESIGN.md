# Плоская «Шахматка» — проект интерфейса

Дата проекта: 14.09.2026. Статус: согласуемый интерфейс и задание на реализацию. Рабочие файлы приложения и база этим проектом не изменялись.

## Решение

Развёртка здания сохраняет пространственный адрес работ: этажи идут сверху вниз, секции стоят рядом. Геометрические пропорции заменены читаемой сеткой. Каждый блок разбит на строки операций выбранной доски и на две равные вертикальные половины: «В системе» и «Новое, %». Имя операции находится в левой половине вместе с текущим процентом.

Пример построен по приложенной схеме: низкая секция 1, высокая секция 2, технические уровни и кровля, рампа и общий паркинг. Названия операций, проценты, идентификаторы и объект — демонстрационные. Их нельзя трактовать как данные реального объекта.

## Основные сценарии

**Ввод с компьютера.** Выбрать доску → выбрать этажи → ввести итоговые проценты справа → проверить дату → «Проверить и записать» → сверить полный пакет → «Подтвердить запись». Только последнее действие создаёт документы факта. Текущие значения слева обновляются после успешного ответа сервера.

**Обход с бумагой.** Выбрать доску и дату обхода → «Бланк обхода» → выбранные этажи или всё здание → формат бумаги → распечатать → вписать проценты на объекте → выбрать ту же доску и дату у компьютера → перенести значения в правые поля → проверить и подтвердить. На бумаге всегда остаются пустые поля для нового факта; экранный черновик туда не переносится.

## Семантика ввода

| Содержимое | Результат |
|---|---|
| Пустая ячейка | Никакой записи по этой операции |
| `0` | Факт нулевого выполнения |
| `1`–`99` | Итоговый процент, статус «В работе» |
| `100` | Итоговый процент, статус «Выполнено» |
| Число, равное текущему | Допустимое повторное наблюдение на выбранную дату |
| Число меньше текущего | Допустимая корректировка с отметкой «уменьшение» при проверке |
| `—`, недоступное поле | Операция не применяется к блоку |
| Дробь, буквы, число вне 0–100 | Ошибка, пакет нельзя подтвердить |

Дата относится к создаваемому факту. Левая половина остаётся текущим состоянием системы. Ввод за прошлую дату не подменяет более поздний факт: после сохранения текущее состояние вычисляется сервером по существующим правилам.

## Раскладка

- В полном здании секции сохраняют горизонтальное место, отсутствующие уровни оставляют пустоты.
- Для работы крупным шрифтом выбран диапазон нескольких этажей. Слева всегда виден общий силуэт с выделенным диапазоном.
- При разных наборах операций сохраняются общие строки выбранной доски; неприменимые строки недоступны.
- Несколько блоков внутри секции и этажа получают дополнительные колонки. Ширина таблицы может превысить исходный контур; матрица прокручивается горизонтально.
- Общий паркинг показан одним широким блоком и имеет один набор вводимых фактов.
- Цвет сопровождает явный процент. Основной синий акцент оставлен для действия и черновика.

В мини-схеме рисунок условный. В реализации уровень рампы и общих помещений нужно определять по связям/отметкам реального объекта, а не по номеру строки примера.

## Печать

Бланк монохромный и сохраняет двухчастные блоки. На каждом листе нужны объект, корпус, доска, адреса блоков, дата факта, момент формирования снимка, ответственный, подпись и нумерация. Печатный шрифт минимум 9 pt, рукописная строка минимум 8 мм. При нехватке места листы разбиваются по целым блокам и этажным полосам; очень высокий блок — по границам операций с повторением адреса и отметкой продолжения.

PDF в комплекте — один демонстрационный лист A3, этажи 8–6. Он не является отчётом по реальному объекту.

## Что можно проверить в интерактивном макете

Смена доски меняет число операций. Доступны диапазоны до кровли и нижние уровни. Можно ввести значения, получить ошибки валидации, перейти к проверке и выполнить демонстрационное подтверждение. Черновики сохраняются при переключении этажей и досок в пределах открытого макета. Вкладка печати показывает пустые поля и позволяет листать образцы для всего здания.

Границы прототипа: подтверждение имитируется в памяти, сеть и реальная база не используются; черновики не сохраняются после перезагрузки; печать в интерактивном фрагменте показывает сценарий, системный диалог не вызывается; переключение A3/A4 меняет подпись образца, полноценный расчёт страниц входит в реализацию; обработка конфликтов, прав, атомарного пакета, точного времени снимка и идемпотентности описана в промпте и должна быть реализована на сервере. Промпт прямо запрещает переносить эти упрощения в продукт.

## Проверка проекта

Макет проверен в Chromium: ввод 0, отказ 101, подтверждение, сохранение черновиков между этажами/досками, 2 и 3 операции, симуляция исторического и текущего факта, пустота печатных полей, десять диапазонов всего здания, наличие паркинга, отсутствие внешнего горизонтального переполнения на 390 px, светлая/тёмная тема и отсутствие ошибок JavaScript. Эталонные экраны открыты и визуально просмотрены. Это проверка прототипа, а не тестирование производственного контура записи в БД.

Проект опирается на существующие функции `work_fact.save_report`, текущие проценты по дате отчёта и явный отбор `block_works`. Для подтверждения нескольких блоков предусмотрено расширение пакетной записи; его нет в демонстрационной логике.
