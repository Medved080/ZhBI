# План: рассчитать калькуляции по всем изделиям (без расценок) — 2026-10-05

Цель: у каждого из 1010 изделий каталога калькулятора известны все НЕЦЕНОВЫЕ входы расчёта, поэтому после заполнения расценок (раздел «Расценки и нормы») стоимость считается полной.
Расценки в план не входят: их заполняет пользователь. Метод и цифры чтения листов — `Docs/calc-vector-ocr.md`; устройство расчёта — `Docs/calc-sync.md` («Расценки, нормы и пересчёт»).

## 3. Этапы

| № | Этап | Что даёт | Оценка, дн. |

| 0 | Расценки (сделано в ветке, не влито в `main`) и «этап B»: номенклатура закладных/труб/петель в прайсе, количества по изделию, строка расчёта | механизм, в который лягут данные этапов 2–4 | 5–7 |
| 1 | Слой «прочитано с листа»: промышленный модуль из прототипа, пакетный прогон по листам, хранение результата отдельно от каталога поставщика (источник, лист, метод, дата, подтверждено ли человеком), приоритет: ручное > прочитанное > каталог | инфраструктура для 2–4 | 4–6 |

Итого ≈ 45–70 человеко-дней одного разработчика; этапы 2б/2в/3б независимы и параллелятся. Оценки грубые: каждая новая серия листов открывает свои исключения.

## 4. Порядок и критерии приёмки

1. Влить этап 0 (после dry-run на копии базы, см. ниже) и сделать 0-B: без него данные этапов 2–4 некуда класть.
2. Этапы 1 → 2а → 4 → 3а: за ≈ 4–5 недель покрывают колонны, подъёмники, шахты, лестничные балки (283) и закладные/трубы/петли.
3. Затем 3б, 2б, 2в по убыванию числа изделий (колонны без ведомости, ригели, плиты).
4. Приёмка по типу изделия: расхождение с проектом ≤ 1% по объёму и ≤ 3% по массе арматуры на выборке; все исключения — в списке «требует проверки», не в расчёте.

## 5. Что нужно от вас

* Нормы по группам: часы на м³ и коэффициент проектный/производственный расход (колонны, ригели, плиты, подъёмники, шахты, панели, лестничные балки) либо решение оставить пока общую норму.
* Приоритет источников при расхождении: ручной ввод > прочитанное с листа > каталог поставщика — подтвердить.
* Листы плит (Пд, ПИ, Пл): подтвердить, что объём и класс бетона берутся из таблицы серии, а не считаются по габаритам.
* Согласие вливать в `main`: миграция 009 применится к реальной базе калькулятора при рестарте сервера на 8000; на её копии проверено, что все 1008 изделий дают ту же стоимость, что их сохранённые снимки (расхождений 0).

## 6. Риски

* Листы ригелей и плит — другой формат таблиц; сроки этапов 2б/2в самые неопределённые.
* Чтение рассчитано на гарнитуру и штамп одного проектировщика; для другого заказчика гарнитуры собираются заново (1–2 часа на гарнитуру).
* «Ведомость стали найдена» — по словам в тексте; разбора таблицы пока нет, реальная достижимость станет известна после 3а.
* Точность чтения измерена на малой выборке; поэтому этап 7 обязателен, а в интерфейсе прочитанное помечается как «не подтверждено», пока человек не проверил.
