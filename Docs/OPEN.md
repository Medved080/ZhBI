строк). Здесь — что НЕ доделано и что ждёт решения пользователя. Закрытый
пункт отсюда удаляется, а не помечается: история закрытия и так остаётся в
`Docs/backlog.md` по дате.

## Статус

Последний релиз в `app/changelog.py` — **v0.57** (08-18; записи добавляются
только по согласованию текста с пользователем). С 08-03 у журнала версий есть
кнопка «Ознакомился»: пока не нажата, окно открывается при каждом входе.

Этапы A–D иерархии «Проект → Объект» **сделаны и выкачены на тестовый
сервер** (08-02, миграция проверена холостым прогоном, числа сошлись).
**Продуктовый контур не трогали**: `main` на GitLab отстаёт больше чем на
сотню коммитов, туда приедет всё разом, включая чистку дообъектного
наследия — свой холостой прогон обязателен, картина будет другая.

## Ждут решения пользователя

- **График СМР: чьи количества правильные** (08-14). Расчёт системы
  расходится с расчётом заказчика на входных данных, не на алгоритме: в его
  ведомости на 279 изделий меньше, чем в модели. Подробности и сверка —
  `Docs/TZ.md` §5.7, требования — `Docs/requirements-2026-08-14.md`.
- **Разобрать накопленные привязки мимо спецификации** (08-14). Новые
  система больше не даёт заводить, старые не чинит (запрет ловит только
  ухудшение). Что накопилось — `scripts/check_contract_coverage.py`; дальше
  решение по каждой позиции.
- **`elements.mark` (текст) и `elements.mark_id` живут рядом намеренно**,
  пока пользователь не сверил разложение по справочнику. Источник правды —
  по-прежнему ТЕКСТ; правка справочника обязана двигать оба. Снимать
  текстовое поле — отдельным решением, не заодно.

## Начато, не закончено

- **Свёртка задвоенных записей справочников — второй шаг** (08-05). Первый
  сделан: марка стала справочником, у всех справочников появилось удаление с
  заменой ссылок, пользователь чистит задвоенное руками. Второй шаг —
  обработка автоматической свёртки записей, различающихся только регистром, и
  регистронезависимое сопоставление при загрузке из внешних файлов (чертёж,
  контрактация, история, график MS Project, массовая правка через Excel).
  Подробности — `Docs/backlog.md` 2026-08-05. **Контрактация с 08-12 уже
  узнаёт регистр** и марки, и контрагента — остальные входы ждут. Посмотреть
  задвоенное — `scripts/check_case_duplicates.py`; свернуть — кнопкой
  обработки `2026-08-06-fold-case-duplicates`.
- **Этап E** — импорт: `/import-dxf` перестаёт заводить объект сам (явный
  выбор до анализа); ключ сопоставления в импортах истории, контрактации и
  графика MS Project — `(object_id, dxf_handle)` вместо
  `(source_file, dxf_handle)`, иначе выгрузка одного здания применится к
  другому. **Импорты контрактации и истории к объекту приведены 08-12**
  (контрактация — явный выбор в форме и не грузится из `Input/`; история —
  договор заводится на объект чертежа; общая проверка `resolve_agreement`,
  `Docs/backlog.md` 2026-08-12). Остальное этапа E не сделано.
- **Хвост этапа C** — отбор строк массовой правки через Excel по доступным
  объектам (сейчас она за системным админом).
- **Хвост этапа 2 по зонам** — диалог согласования расхождений по зонам при
  переимпорте (у элементов такой диалог есть, у зон нет).

## Временное, подлежит удалению

- **Обработка «Заполнить пустые „Объект“ и „Проект“»** (`app/fill_scope.py`,
  08-03) — лечит дообъектное наследие: записи, заведённые до появления у них
  объекта. Помечена временной и в меню, и в форме; удалить вместе с
  наследием, новые такие записи система заводить не даёт. Пока наследие есть,
  форма контракта показывает безобъектные договоры администратору сервиса.
- **`_attempt_migration_recovery` в `on_startup()`** — временный механизм,
  убрать только по запросу пользователя.
