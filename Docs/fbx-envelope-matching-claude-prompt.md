## 2. Подтверждённый дефект метрики

`object_geometry_features.py` берёт контуры ВСЕХ элементов категории «Стены» и отбирает длинные рёбра. Он не строит наружный контур здания. Внутренние стены, торцы и обе стороны стен остаются допустимыми целями.

`evaluateTransform` в `auto-align.js` для каждой точки FBX ищет ближайший отрезок из этого набора. Ничего не требует от остального конструктива. Coverage означает долю точек выбранной FBX-выборки, около которых нашлась какая-либо стена в радиусе поиска, а не долю правильно совмещённого здания. Направления и соответствующие высотные срезы не ограничивают этот поиск. `perPartScores` использует тот же общий набор целевых стен, поэтому не устраняет проблему.

Точная воспроизводимая демонстрация текущего дефекта, мм:

```js
import { evaluateTransform, buildSegmentGridIndex } from './app/static/external-models/auto-align.js';
const corners = [[0,0],[20000,0],[20000,16000],[0,16000]];
const target = corners.map(([x1,y1],i)=>({x1,y1,x2:corners[(i+1)%4][0],y2:corners[(i+1)%4][1],z0:0,z1:3000}));
target.push({x1:4000,y1:0,x2:4000,y2:16000,z0:0,z1:3000}); // внутренняя стена
const facade = [[4000,0],[20000,0],[20000,16000],[4000,16000]];
const points = [];
for (let e=0;e<4;e++) {
  const a=facade[e], b=facade[(e+1)%4];
  for (let i=0;i<=40;i++) points.push({x:a[0]+(b[0]-a[0])*i/40,y:a[1]+(b[1]-a[1])*i/40});
}
const result=evaluateTransform(points,target,buildSegmentGridIndex(target,2000),0,[0,0],3000);
console.log(result.coverage,result.rmsResidualMm);
```

Запуск из корня репозитория через `node --input-type=module` даёт coverage=1 и RMS≈3e-13 мм. При этом полоса конструктива шириной 4000 мм осталась за фасадом. Это специально несовместимые наружные размеры: ожидается отказ по геометрическому несоответствию, а не успех. Пример доказывает слепую зону оценки, но не доказывает, что реальные исходники пользователя несовместимы.

## 3. Сначала извлечь сопоставимые наружные контуры

Перестать использовать набор всех стен как эквивалент оболочки здания. Сначала установи, какая геометрия этого объекта действительно доступна: реальные внешние контуры перекрытий/объёмов, наружные стены с достоверным признаком или только отдельные стены/помещения/условные блоки.

При наличии контуров перекрытий/объёмов используй их объединение и наружные границы на репрезентативных высотах, сохраняя вогнутые участки и реальные разрывы. Не заменяй здание общим bbox/convex hull: они уничтожают форму низкой части и углы комплекса. Если есть только стены, внешний контур надо восстановить и проверить топологически; категория «Стены», максимальная длина и близость к краю bbox не являются классификатором наружной стены. Неполные данные должны давать явный отказ/пониженную применимость, а не выдуманный замкнутый контур.

Для FBX извлекай внешнюю оболочку/контуры сечений соответствующих частей из геометрии, не проекции всех трёх рёбер каждого вертикального треугольника. На первом этапе визуально выведи рядом две сравниваемые геометрии в ортографическом плане: внешний контур FBX, внешний контур конструктива, использованные срезы и части. Текстуры, деревья, кровельные ограждения, внутренние стены и дубли не должны определять положение оболочки.

Разделение по высоте должно реально сохранять соответствие частей. Имеющийся `clusterSpatialParts` объединяет по соседству в XY; примыкающий низкий корпус может оказаться в той же связной компоненте, что башня. Это не заменяет сечения выше и ниже кровли низкой части. Не сопоставляй верхнюю башню с плановым следом низкой части просто потому, что отрезок оказался рядом. При неизвестной общей высотной отметке сначала установи соответствие срезов/уровней, а не сравнивай одинаковые абсолютные Z без преобразования.

Перед дальнейшей оптимизацией измерь размеры наружных частей в их собственных направлениях, расстояния между ними и доступные уровни. Общий axis-aligned bbox повернутого файла для такой проверки непригоден. Если пропорции расходятся сильнее объяснимой толщины фасада/точности исходных данных, покажи конкретное несовпадение и не продолжай подгонку масштаба.

## 4. Проверять геометрический результат, а не только ближайшие точки

Сопоставляй наружный контур с наружным контуром; допустимые соответствия должны учитывать направление/сторону и сопоставимый срез. Уточнять угол и перенос можно уже имеющимися средствами, но на исправленных признаках.

Добавь двустороннюю оценку сравнимых наружных границ: FBX→конструктив и конструктив→FBX, отдельно по сторонам, башне и низкой части. Не добавляй обратный поиск по ВСЕМ внутренним стенам: они и не должны совпадать с фасадом. Для частичных моделей учитывай явно известную область применимости, не отбрасывай неудобные участки после подбора.

Дополнительно проверяй выступание несущего объёма за ожидаемую оболочку по выбранным сечениям: длину/долю проблемного внешнего контура, характерную и максимальную глубину выступания, место на схеме. Учитывай балконы, козырьки и другие допустимые выступы, а также толщину облицовки. Не превращай тест в правило «каждый элемент обязан быть внутри» и не используй вложенность как единственный критерий: слишком большой фасад тоже может всё накрыть.

Проверку выполняй на независимых внешних признаках, не только на урезанной выборке оптимизации. Порог задавай в единицах геометрии с объяснением допуска. Сводный coverage в 90% при ошибках в метры на одной стороне не должен делать кандидат пригодным.

Статус `ambiguous` и выбор вариантов нужны, только если несколько вариантов прошли проверку геометрической пригодности. Если все плохие — «Совмещение не найдено», исходное положение сохраняется; неподходящие варианты можно показать лишь как диагностику с выделением ошибки. Не навязывай выбор одного из трёх. Сначала нужно найти/подтвердить правильное положение, а не только убрать кнопки плохих.

Попутно исправь `fineRefine`: в конце вызывается `icpRefine(maxIters:1)` ради оценки; возвращаются прежние theta/t и метрики уже дополнительно сдвинутого результата. Использовать чистую `evaluateTransform` без мутации либо возвращать тот же transform, который оценён. Это отдельная ошибка согласованности; она не заменяет исправление оболочки.

## 5. Приёмка именно этого дефекта

1. Пример внутреннего прямоугольника выше после исправления не проходит проверку пригодности, несмотря на идеальное совпадение части стен.
2. Правильная оболочка с известным поворотом/переносом и множеством внутренних стен: найденное положение не зависит от количества, длины и порядка внутренних стен.
3. Сдвиг на один шаг повторяющихся стен, разворот 180°, несовместимые ширины/расстояния частей, частичная модель: корректные отказы/неоднозначность, без растяжения и ложного успеха.
4. Башня и низкая часть примыкают и стоят на общей земле; верхний срез и нижний проверяются отдельно. Уточнение башни не ухудшает низкую часть незаметно для метрики.
5. Наружный слой с известной толщиной, балкон и козырёк: допустимые выступы не ломают правильную привязку. Связанные ground/facade сохраняют относительное положение и высоту.
6. Показанные пользователю кандидаты −33.8877° / +146.3933° / −33.6504° воспроизвести на разрешённом наборе именно этого здания и объяснить ошибку по сторонам/частям. Числа X/Y из скриншота относятся к его сохранённым anchors; не переносить offsets на другую БД без проверки B и A.

В отчёте нужны наложенные внешние контуры в плане, размеры соответствующих частей, области выступания, показатели до/после и сохранённая трансформация. Натурную правильность подтверждать на паре «этот фасад — этот конструктив». Если пара недоступна, реализуй и проверь extraction/оценку на разрешённых данных, но прямо укажи недостающий набор для натурной приёмки. Не называй ещё один удачный тест одинаковых прямоугольников доказательством работы на здании пользователя.
