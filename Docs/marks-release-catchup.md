# Восполнение справочника марок при обновлении

Исправление от 10 ноября 2026 года для локального выпуска СНЗ.

Старая обработка `2026-08-05-marks-catalog` уже была отмечена выполненной, когда появились дополнительные позиции контрактов. Поэтому `run_pending()` её пропускал, а первый принудительный повтор на холостом прогоне добавлял марки. Это было восполнение новых данных после исторического успеха, а не бесконечное создание дублей при неизменном входе. На обезличенной копии обнаружено 28 таких марок.

Добавлена отдельная обработка `2026-11-09-marks-catalog-catchup`, которая выполняется при первом старте обновлённого сервера независимо от прежнего маркера. Она заполняет только отсутствующие точные ключи объекта, типа и имени. Существующие марки и их ID не переименовываются, ручные `elements.mark_id` не перезаписываются, текст марок и позиции контрактов сохраняются. Запросы выбирают отсутствующие ключи через `NOT EXISTS`, поэтому повторы не расходуют счётчик AUTOINCREMENT на проигнорированные вставки. Пустая ссылка изделия заполняется только при точном соответствии.

В `scripts/dry_run_migration.py` таблица `marks` добавлена в сравнение содержимого, чтобы изменение имени при прежнем количестве строк также считалось ошибкой. При замечании скрипт теперь завершает работу с кодом 1; успешный результат — код 0 и пустой повтор.

Проверки:

- `scripts/test_marks_release.py`: пять проверок на временной синтетической базе, включая поздний контракт после старого успешного маркера, три точных повтора, сохранность ссылок и счётчика ID, область/регистр, отсутствие типа, изменения без роста числа строк, ненулевой код отказа.
- Полный холостой прогон на отдельной копии `zhbi.anon.db`: первый проход восполнил 28 марок, принудительные повторы всех обработок не изменили число или содержимое проверяемых таблиц; ключи и данные целы.
- Полный холостой прогон на согласованном SQLite-снимке базы локального сервера 8000: код возврата 0, повтор пуст, замечаний нет. Рабочая база при прогоне не изменялась; содержимое целевого снимка в отчёт не выводилось.
- Объединённый кандидат с текущими незавершёнными изменениями рабочей копии: пять проверок марок, 17 проверок СНЗ и 19 проверок интерфейса в Chrome прошли.

Порядок установки: сохранить незавершённые изменения → снять резервную копию рабочей базы → остановить сервер с автоматической перезагрузкой → перенести ветку СНЗ и исправление → восстановить все незавершённые правки → запустить основной сервер → проверить `/health`, `/v2`, изменённые статические файлы и новый процесс → проверить повтор на снимке уже обновлённой базы. Корпоративные `develop`/`production` этой локальной установкой не обновляются.
