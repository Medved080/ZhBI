# Общие правила исполнителей переноса V1 → V2 (обязательны)

Всё общение и комментарии в коде — ПО-РУССКИ. Проект — ЖБИ-трекер. Читать `/Users/max/zhbi-tool` можно, ПИСАТЬ туда нельзя.

## Цель
Пользователь ведёт повседневную работу в V2 (`http://127.0.0.1:8000/v2`), V1 остаётся полностью рабочей резервной. «Переход в V1», заглушка и отключённая кнопка — НЕ реализованная функция.
Бизнес-смысл операций НЕ менять. Новые сущности, изменения схемы БД, разрушительные преобразования, неоднозначные бизнес-решения — не делать: записать точный блокер/вопрос в файл прогресса и
перейти к независимой функции. Не подменять отсутствующую возможность похожей по названию операцией.

## Ветки и запреты
* Базовая ветка — `feature/v2-next` (worktree `/Users/max/zhbi-next`). Создай свой worktree: `git -C /Users/max/zhbi-next worktree add /Users/max/zhbi-w-ИМЯ -b feature/v2-ИМЯ feature/v2-next` и
  `ln -s /Users/max/zhbi-tool/.venv /Users/max/zhbi-w-ИМЯ/.venv`. Коммить малыми законченными шагами (по-русски, в конце `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`). В другие ветки не сливай, push нельзя.
* ЗАПРЕЩЕНО: порты 8000, 8010, 8020; каталог `/Users/max/zhbi-tool` (там `--reload` следит за `*.py`); боевая БД; push; корпоративный сервер; смена настоящих паролей и прав; ослабление защит (отказ среды не обходить — сообщить).
* НЕ завершай процессы по имени (`pkill -f …`): останавливай только процессы СВОИХ портов (`lsof -tiTCP:ПОРТ -sTCP:LISTEN | xargs kill`). Соседние исполнители работают параллельно.
* Диск ограничен: не копи копии БД; серверы поднимай только через `scripts/real_auth_server.py` (штатные копии «перед стартом» он кладёт во временный каталог), каталоги проверок удаляй по завершении.
* Не открывай браузерную панель приложения (`mcp__Claude_Browser__*`) — для браузера используй `scripts/cdp.mjs`.
* Рабочий каталог `/private/tmp/...scratchpad` может быть очищен системой: постоянные проверочные скрипты держи в репозитории (`scripts/`), копию БД-источник пересоздавай: `python3 -c` со штатным sqlite backup из `/Users/max/zhbi-tool/data/zhbi.anon.db` (обезличенная копия, читать можно) в свой каталог.

## Стенд (настоящий backend, настоящий вход)
* `.venv/bin/python scripts/real_auth_server.py <база-источник> <ПОРТ> <каталог_копии>` (в фоне) — НАСТОЯЩИЙ `app.main:app`; логины `admin`, `user3` (админы), `user2` (роль user, доступ к объекту 1), `user4` (view); пароль печатается при старте
  (тестовый, только для КОПИИ). Вход — настоящей формой V2 или `POST /login`. Подмена авторизации в проверках запрещена. Ограниченные роли — входом под `user2`/`user4`; неполные роли готовь SQL в КОПИИ.
* Браузер: `scripts/cdp.mjs` — безголовый Chrome с НАСТОЯЩИМИ событиями мыши и клавиатуры (`launch → goto/eval/waitFor/click/clickSel/drag(shift)/wheel/type/key/shot/offline/viewport`, `requests`, `consoleLog`, `exceptions`). Жесты
  (щелчок, Ctrl/⌘-щелчок, рамка Shift+перетаскивание, колесо, перетаскивание) проверяй ЭТИМ, а не внутренней командой. Образцы полных наборов: `scripts/verify_model_ui.mjs`, `scripts/verify_admin_ui.mjs`, `scripts/picker_verify/*`,
  `scripts/verify_mfr_browser_*.mjs`, `scripts/v2_tests/exchange/chk_*.mjs`, `scripts/verify_alloc_browser.mjs`; подготовка данных распределения — `scripts/prep_alloc_case.py`.
* Проверка изменяющей операции завершена, только если на настоящем backend, в браузере, на временной копии пройдено: успех и результат ПОСЛЕ перезагрузки; отказ при недостаточных правах (403 от сервера под `user2`/`user4`); серверная валидация;
  конфликт устаревших данных; двойная отправка (один запрос); сетевой сбой и неизвестный исход (`b.offline(true)`/оборванный ответ: без автоповтора, сверка с сервером); отсутствие частичных и побочных изменений (SQL до/после);
  правдивый журнал (событие только для сохранённого); совместимость затронутых экранов V1 на том же сервере. Для групповых опасных операций — конкуренция и полный откат при отказе внутри пачки. Не ослабляй проверки ради зелёного результата;
  падение отделяй от старых падений доказательством.
* Backend: любые правки — совместимые и минимальные; писатели берут блокировку записи первым действием (`app.db.begin_write`, образец `app/allocation.py`, `app/element_ops.py`), журнал — `activity.defer_begin/defer_flush/defer_end` для операций с откатом;
  необязательные поля «ожидаемого состояния» (`expected_*`/`version`) — V1 их не шлёт. Схему БД НЕ менять. Новые эндпоинты — в новых файлах-роутерах, подключение в `app/main.py` одной строкой рядом с `allocation_router`. Новое событие журнала —
  строка в `app/activity_actions.py`.

## Шлюз записи V2 (`app/static/v2/write-gate.js`)
«Запрещено всё, что не разрешено явно». Для КАЖДОЙ включаемой операции — отдельная строка `allowed: true` в POLICY: метод + точный путь + `onlyKeys` и/или `check(body, query, pathWithQuery)` (жёсткая форма тела/запроса/загрузки; правила форм — в отдельных модулях
`*-rules.js`/`*-gate.js`, импортируются в начале файла) + `proof`. Строки — ТОЛЬКО в блоке своей области (`// ==== область: ИМЯ ====`). Общую разрешающую настройку не вводить. Закрытую тобой отключённую строку удали или сузь.
`node scripts/gen_v2_write_policy.mjs` НЕ запускай (документ пересоздаю при интеграции).

## Интерфейс и дизайн (без редизайна)
Существующие компоненты V2 (`dialogs.js`, `read-screen.js`, `screen-view.js`, `dict-edit.js`, `api.js`, `focus.js`, `icons.js`, `styles.css`). Едины шрифты, размеры, отступы, поля, кнопки, таблицы, диалоги, состояния загрузки/ошибки/пустоты, подтверждения и
