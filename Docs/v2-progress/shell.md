Ветка `feature/v2-shell` (worktree `/Users/max/zhbi-w-shell`, от `feature/v2-next`). Порты проверок — 8210–8219,
копия обезличенной БД (`data/shell_check/case.db`, готовится `scripts/shell_verify/prep_shell_case.py`, только

## 1. Что сделано (по пунктам задания)

### п.1 — Выбор объекта в шапке

Кнопка вместо `<select>` (`app/static/v2/shell-object-picker.js`, вызывается из `main.js`): открывает окно —
поиск по названию объекта/проекта/адресу; «Закреплённые» сверху (отдельная секция, объект в ней не дублируется
в «С данными»/«Без модели» ниже); «С данными»; ниже свёрнутая по умолчанию «Без модели»; иерархия проект →
объект; названия слева с многоточием и title на полный текст, счётчик элементов — нерастягиваемой колонкой
справа; текущий объект — галочка. Группировка и сортировка — ТО ЖЕ правило V1 (`app/static/app.js::renderObjectSwitchList`,
перенесено 1:1: сначала проекты «с данными», единственный объект в проекте — без заголовка, проект с ТЕКУЩИМ
объектом внутри раскрыт по умолчанию). Архивные — правило видимости V1 (`objectSwitchArchived`/`objectSwitchVisible`),
чекбоксом «Показывать архивные», `localStorage`. Закрепление (до 200 объектов) и «последний объект» — за
пользователем (см. §backend ниже). Смена объекта идёт через сторож несохранённых данных (`main.js::changeObject`,
переиспользует существующую логику `guardLeave`/`hasUnsavedChanges`), рабочие места и права пересчитываются, как
раньше. Управление мышью (клик вне закрывает), клавиатурой (стрелки двигают выделение без потери фокуса поля
поиска, Enter выбирает, Esc закрывает и возвращает фокус на кнопку), видимый фокус — реализовано.

### п.2 — Левая навигация: три состояния

`app/static/v2/shell-nav.js`. А) свёрнутая полоса 50px (в диапазоне 48–52 из задания), кнопки «Меню» и «Найти
раздел», «Начало» и значки рабочих мест (не все пункты), подсказки по наведению И по фокусу (CSS `::after` от
`data-tooltip`, не только `title`, которого не видно с клавиатуры). Б) временно открытая — `position:absolute`
поверх содержимого (сам «слот» в раскладке остаётся узкой полосой — раскладка не меняется, схема не
пересчитывается), закрывается успешным переходом/Esc/клику вне; при отказе сторожа (несохранённые данные) —
остаётся открытой, экран и ввод не теряются. В) закреплена — булавка, реальная ширина в раскладке, содержимое
подвигается; повторный клик открепляет; выбор — за пользователем. Изначально — свёрнута. Не отменяется
самовольно при смене раздела. На узком окне (`window.innerWidth < 980`, `NARROW_WINDOW_PX`) закреплённая ведёт
себя как временная — БЕЗ стирания сохранённого предпочтения; при возврате ширины — восстанавливается. Текущее
рабочее место подписано в шапке (`.v2-head-section`) независимо от состояния меню.

### п.3 — Регулировка ширины

Разделитель (`.v2-shellnav-resize`) — широкая зона захвата (12px), тонкая видимая линия, `cursor:col-resize`,
подсветка при наведении/фокусе. Начальная 260px, минимальная 220px, максимальная 380px, дополнительно поджата
под ширину окна (`effectiveMaxWidth()`, резерв 420px под содержимое). Перетаскивание — `setPointerCapture` +
`pointer-events:none` на `.ws-frame` (кадр схемы) на время драга — тот же приём, что уже проверен у правой
панели рабочего места (`workspace.js::rz`), указатель не теряется над iframe. `user-select:none` на время драга,
снимается по отпусканию. Клавиатура — стрелки, Home/End, `role="separator"`, `aria-valuenow/min/max`; двойной
клик — сброс к 260px. Не выполняется перезагрузка схемы при изменении ширины — только пересчёт размеров (сам
V1 внутри iframe уже слушает `ResizeObserver` на `#stage`, отдельно ничего не добавлялось). Горизонтальной
прокрутки страницы нет на 1920×1080 и 1366×768 (проверено).

### п.4 — Структура меню

Убраны из вида: числа у заголовков групп, метки «чт.»/«прав.»/«обмен»/«экспорт» (данные для документации
остаются в `screens.json`/матрице, только не рисуются). Экран, который ДЕЙСТВИТЕЛЬНО открывается в V1 —
подписан фразой в `title` пункта («…— откроется в текущем интерфейсе»), не аббревиатурой; значок «↗» —
нейтральный визуальный маркер, полный текст — в `title`/`aria-label`. Ограничения внутри доступного в V2 экрана
по-прежнему показывает существующий `updateGateNote` (текст различает «нет права» — сервер отвечает 403,
«функция ещё не перенесена» — операция отключена шлюзом с причиной, «временно недоступна» — ошибка сети/сервера);
эта часть НЕ переделывалась, только унаследована. Организация: «Рабочие места» — короткий НЕсворачиваемый блок
сверху (с учётом типа объекта и прав — та же `screenAllowed`, что и везде); дальше сворачиваемые группы;
«Администрирование»/«Настройки»/«Обучение и справка» — отделены чертой снизу. По умолчанию раскрыта ТОЛЬКО
группа текущего экрана (правило: группа без явной записи в сохранённом состоянии раскрыта, если в ней текущий
экран, иначе свёрнута); пользователь может свернуть и её — это тоже явная запись, переживает перезагрузку.
Поиск — по названиям пунктов ВСЕХ доступных разделов (не только раскрытых групп) и по названиям групп (сохраняет
группу целиком, если совпало её название); НЕ переписывает сохранённое раскрытие — временное раскрытие на время
поиска, после очистки — прежнее состояние. Активный пункт — фон и полоса слева (`aria-pressed`, тот же приём,
что и раньше); заголовки групп — отдельный визуальный язык (прописные, приглушённый цвет, не кнопка-пункт).

## 4. Найденные дефекты (исправлены)

Все — найдены живой браузерной проверкой, не умозрительно.

1. **Поиск в окне выбора объекта терял совпадения.** `visible(row)` дублировала проверку текста запроса ПОВЕРХ
   уже нормализованного (`trim`+`toLowerCase`) фильтра в `render()`, но использовала СЫРОЙ, ненормализованный
   `query` — при другом регистре введённого текста строка не находилась вовсе. Исправлено: `visible()` отвечает
   только за архивную видимость, поиск — только в `render()`.
2. **Не перенесено правило V1 «проект/раздел с текущим объектом раскрыт по умолчанию».** В окне выбора объекта
   многообъектный проект и раздел «Без модели» не учитывали, что текущий выбранный объект может быть внутри —
   пользователь открывал окно и не видел свой же текущий объект без лишнего клика. Добавлено (`projectGroupHtml`,
   верхний уровень «Без модели»).
3. **Фокус не возвращался на кнопку «Меню» после закрытия временной панели.** `render()` пересобирает всю
   разметку через `innerHTML` — ссылка на кнопку, сохранённая ДО пересборки, указывала на уже удалённый узел;
   `.focus()` на нём — молчаливый no-op. Исправлено: хранится `id` кнопки, узел находится заново из свежего DOM.
4. **Подсказка «откроется в текущем интерфейсе» приближала классификацию, а не повторяла её.** Первая версия
   `screenOpensInV1()` не учитывала, что у нескольких `impl` (`read`, `dict-edit`, `card-edit`, `export-form`,
   `access-view` и др.) реальное монтирование в `main.js::openSection` зависит от СОПУТСТВУЮЩЕГО поля конфигурации
   экрана (например, `impl:"read"` без блока `read` реально падает в `mountScreenView`, то есть открывается в
   V1, несмотря на «общий» с рабочими read-экранами `impl`). Переписано на точное повторение условий
   `openSection` (включая прямой импорт `hasAdminScreen`/`hasExchangeOp` вместо приближения по префиксу `impl`).
5. **Клавиатурная регулировка ширины отвечала только на ПЕРВОЕ нажатие стрелки.** Та же ловушка, что в п.3: после
   `render()` новый узел разделителя не наследует фокус старого. Исправлено (`afterResize()`: `render()` →
   `el.querySelector("#v2-shellnav-resize")?.focus()`), тем же приёмом, что уже применён к полю поиска.
6. **После перетаскивания мышью стрелки клавиатуры не работали сразу** (нужен был отдельный Tab). Причина —
   `e.preventDefault()` в обработчике `pointerdown` (нужен, чтобы драг не выделял текст страницы) как побочный
   эффект отменяет и штатную фокусировку элемента браузером на mousedown. Исправлено явным `rz.focus()`.
7. **Синтаксическая ошибка, ронявшая ВЕСЬ V2 целиком.** При добавлении HTML-комментария с обратными кавычками
   внутри JS-шаблонного литерала (`app/static/v2/main.js`) кавычки преждевременно закрывали литерал —
   `SyntaxError: Unexpected identifier 'select'`, ничего не рендерилось (даже форма входа). **`node --check
   <файл>` эту ошибку НЕ ловит** (видимо, из-за иной обработки ESM-файла без флага) — поймана только
   `node --input-type=module --check < файл`, как и предписывает BRIEF; после находки все свои JS-файлы
   перепроверены именно так. Урок зафиксирован в этом отчёте — если другие исполнители используют `node --check
   <файл>.js` без `--input-type=module`, стоит перепроверить их тоже (не входило в эту задачу).

## 5. Отклонения от сценария проверки (раздел 5 задания) и почему

* **«Одинаковые названия объектов в РАЗНЫХ проектах» — построить НЕЛЬЗЯ.** И `projects.name`, и `objects.name`
  объявлены `UNIQUE` в самой схеме БД (не индекс приложения — ограничение таблицы, `CREATE TABLE`). Это не
  пробел подготовки данных, а инвариант БД; менять схему запрещено (BRIEF). Ближайший реальный аналог — почти
  неразличимые названия («Корпус 1 (двойник 1..4)» в четырёх разных проектах, отличаются только скобкой) —
  проверено: выбор идёт по `id` (`P4.1–P4.3`), в коде НЕТ ни одного места, где объект ищется/сравнивается по
  имени, а не по `id`.
* **Подсказка «откроется в текущем интерфейсе» проверена на функции классификации, не на живом пункте меню.**
  На ТЕКУЩЕМ состоянии `screens.json` (после находки и исправления дефекта №4) не осталось ни одного пункта
  меню (кроме служебной записи группы `home`, которая в меню не попадает вовсе), где `screenOpensInV1()`
  возвращала бы `true`, — у каждого раздела уже есть своё монтирование в V2 (хотя бы каркасом). Хорошая новость
  для проекта в целом, но живого примера для этой конкретной проверки нет; функция проверена напрямую
  (`N5.1–N5.4`) и сверена на СУЩЕСТВУЮЩЕМ реальном пункте на отсутствие технической аббревиатуры (`N5.5`).
  Появится экран без монтирования — код уже готов его подписать.
* **Стенд `scripts/v2_tests`/`node scripts/picker_verify/stand.mjs`** не расширялся под новую оболочку: задание
  просило поддерживать его, «если меняешь проверяемое им поведение» — фейковый backend этого стенда не содержит
  сцен, завязанных на левую навигацию/выбор объекта как таковые (сценарии `cp`/`gt`/`ws` относятся к другим
  областям); расширение стенда под shell — отдельный объём работы, не начато.

## 7. Вопросы пользователю

1. **Порог «узкого окна» для автоматического разжатия закрепления** (`NARROW_WINDOW_PX = 980` в
   `shell-nav.js`) — подобран мной по смыслу (закреплённая панель 220–380px не должна оставлять содержимому
   меньше ~600px), в задании числа нет. Подходит порог или нужен другой?

   ширины панели под размер окна) — то же самое, подобрано по смыслу, число не задано заданием.
3. **Порядок закреплённых объектов** — сейчас в порядке дерева `/projects-tree` (естественный, стабильный), а не
   в порядке, в котором пользователь их закреплял. Задание не уточняет, важен ли порядок закрепления как таковой
   — если нужен порядок «по кликам», это лёгкая правка (хранить сам порядок, а не полагаться на порядок дерева).

   дождаться общего набора иконок, если он планируется в другой задаче)?
