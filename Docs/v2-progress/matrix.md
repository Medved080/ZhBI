Ветка `feature/v2-matrix2` (от `feature/v2-next`), рабочая копия `/Users/max/zhbi-w-matrix2`. Серверы и браузер не использовались — задача анализ кода;
на 8000 ничего не публиковалось, `write-gate.js`/`screens.json`/`main.js`/`workspace.js`/backend не менялись. Продолжение работы исполнителя «matrix»
(`Docs/v2-progress/matrix.md` прежней версии — история сохранена в git). Задача пользователя: «Наличие маршрута или разрешения в шлюзе не является
доказательством работоспособности пользовательского сценария» — матрица не должна занижать реализованное (пропуская непрямые вызовы V2) и не должна
завышать проверенность (принимая самоотчёт `proof` строки шлюза за доказательство).

## Что сделано

### 1. Разбор непрямых вызовов V2 (главная причина неверных строк)

Генератор считал операцию вызванной V2, только если путь — прямой строковый/шаблонный литерал в аргументе `api.method(...)`. Реальный код вызывает пути
и через: свойства объектов-конфигураций (`cfg.path(v)` — контракты/график/история импорта, `exchange-import.js`), параметры функций-обёрток
(`api.patch(path, ...)` внутри `patchChecked(kind, id, path, body, current)` — контрагенты/договоры/спецификации/контракты, `counterparties.js`), и
недостающий метод API-обёртки (`api.fetchFile` не было в списке методов вообще). Добавлено:

* `V2_API` дополнен `fetchFile` (метод по умолчанию GET, уточняется опцией `{method: "..."}`) — было ПОЛНОСТЬЮ пропущено, поэтому
  `POST /elements/bulk-edit/export`, `GET /import-templates/{key}/sample` не находились вовсе.
* `scan_object_props` + `V2Resolver.chain_call_alts` — запасной разбор `объект.свойство(...)`, когда `объект` не резолвится напрямую: индекс по ВСЕМ
  объектным литералам файла с таким именем свойства (по токенам, не регуляркой). Закрывает `cfg.path(v)` → `POST /import-contracting-xlsx`,
  `POST /import-history-xlsx`, `POST /import-schedule-xlsx`.
* `js_functions` теперь разбирает и параметры функций (`_parse_params`); `V2Resolver.param_alts` — когда идентификатор не резолвится локальным
  присваиванием, но является параметром охватывающей именованной функции (в т.ч. через замыкание во ВЛОЖЕННОЙ функции — подъём по цепочке владельцев),
  ищет вызовы этой функции ПО ИМЕНИ в файле и раскрывает аргумент на той же позиции. Закрывает `createChecked`/`patchChecked` в `counterparties.js` →
  `POST/PATCH /counterparties`, `/agreements`, `/specifications`, `/contracts` (8 операций).
* Резервный регэксп-проход `v2_calls_regex_fallback` — НЕ основной способ разбора, страховка от подтверждённого дефекта самого токенизатора
  `scripts/inventory_v1_ui.py` (см. «Обнаруженный дефект» ниже): добавляет (метод, путь) ТОЛЬКО если структурный разбор не нашёл его вовсе нигде в файле.
  Закрыл `PATCH /roles/{key}`, `GET /roles/{key}/delete-plan` (`users-access.js`), которые токенизатор терял целиком.

Даны в задании как примеры неверных строк — все пять подтверждены и исправлены: `POST /import-contracting-xlsx`, `POST /import-history-xlsx`,
`/import-schedule-xlsx`, `/elements/bulk-edit/export` — переведены генератором в «реализована в ветке»; `/objects/{id}/block-works/bulk-edit/apply`
(без `-strict`) — ПРОВЕРЕН отдельно: V2 действительно НЕ вызывает именно этот маршрут (он замещён НОВЫМ маршрутом `apply-strict`, см. докстринг
`app/block_ops.py`); честно оставлен «только переход в V1» — подмена было бы обманом. Область (`exchange`→`mfr`) для этой группы исправлена отдельно (см. п.3).

НЕ разбор вызовов/путей — оргструктура файла) + перекрытие области операции областью её строки шлюза, когда она есть и однозначна. Итог: `analyze` и

## Обнаруженный (НЕ устранённый — вне списка файлов этого задания) дефект токенизатора

`scripts/inventory_v1_ui.py` (функция `tokenize`, ветка обратных кавычек) неверно отслеживает глубину вложенности `${…}` на сложных литералах, где
внутри дырки лежит СВОЙ backtick-литерал или объектный литерал со своими `{`/`}` — глубина считается плоско по паре `${`/`}`, без различения уровня
вложенности. На `app/static/v2/users-access.js` (длинная HTML-форма редактора роли) это обрывает отслеживание раньше настоящего конца литерала:
хвост реального кода (включая `api.patch(\`/roles/${role.key}\`, …)`, строка 1741) целиком выпадает из потока токенов, а символы `<`/`/` из
последующей HTML-разметки по эвристике «похоже на regex» пожирают ещё один большой кусок кода до случайного совпадения с `/roles/` много строк
спустя. На `app/static/v2/counterparties.js` тот же класс дефекта проявляется мягче — часть вызовов после сложных HTML-шаблонов получает НЕВЕРНЫЙ
номер строки (систематическое смещение), но сама СВЯЗКА (метод, путь) не теряется (совпадает с другим вызовом того же маршрута в файле). Файл вне
списка, который может менять этот исполнитель (`scripts/gen_v2_operations.py`, `Docs/v2-operations-matrix.{md,json}`, `Docs/v2-progress/matrix.md`) —
заведена отдельная задача (chip «Fix nested-template-literal bug in inventory_v1_ui.tokenize», session `task_0234dbdb`), в генераторе — резервный
регэксп-проход (п.1) закрывает найденные конкретные пропуски, самопроверка держит расхождение (291 структурных вызовов ≠ 295 по regex) видимым, а не
скрытым. `--strict` из-за этого возвращает код 1 — ожидаемо, причина документирована в тексте самой проблемы.

## Как считается (без изменений с прошлой версии, кратко)

Строка — один маршрут backend (`ast` по `app/**/*.py`, права — `assert_*`/`has_*`/`require_*`/`Depends`) плюс клиентские операции без API. V1 и V2 —
токенизатор `inventory_v1_ui.tokenize` (см. дефект выше) с графом вызовов (V1) и раскрытием путей по `screens.json`/объектным литералам/параметрам
функций (V2, новое — п.1). Шлюз — `POLICY` из `write-gate.js`, вычисляется настоящим `node`. Область/раздел/экран — `RULES` по пути + перекрытие
областью блока шлюза для операций с явной строкой (новое — п.3). Полный перечень источников — докстринг `scripts/gen_v2_operations.py`.

## Что нужно знать при чтении

* Точки входа V1 и «экран операции» — по графу вызовов и правилам пути, приближённо; при расхождении верить коду.
* «Заблокирована внешним условием» ≠ «не проверена»/«не работает»: причина всегда конкретна и указывает на документ-источник
  (`blocked_reason` в JSON, текст действия в MD). Список — `Docs/v2-progress/blockers.json`, обновлять при появлении/снятии блокеров.
* «Не проверена» в столбце проверки — это ОТСУТСТВИЕ найденного набора, а не доказательство отсутствия проверки: набор может ссылаться на путь не
  литералом (через переменную/константу), которую этот механизм не восстанавливает (в отличие от разбора самих V1/V2-вызовов). Прежде чем публиковать
  операцию как проверенную «на глаз» — свериться со списком `checks.sources` в JSON.
