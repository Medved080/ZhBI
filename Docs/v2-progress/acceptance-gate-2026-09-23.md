# V2 — проверка оставшихся пометок «только V1» (2026-09-23)

Цель — не считать число зелёных экранов доказательством полноты, а сверять конкретное действие V1 с действием V2 и его результатом. Инвентаризатор V1 (`scripts/inventory_v1_ui.py`, HTML-дерево + токенизатор JS с самопроверкой) на текущем коде: 71 пункт меню, 83 модальных экрана, 38 кнопок вне меню/модалок; разбор и текст разметки совпали по 1185 `id`, разбор и текст JS — по 1918 `getElementById`. Это инвентарь, не утверждение, что все действия прошли живую приёмку.

Не закрыто этим проходом: сквозная повторная приёмка всех ролей и всех 76 записей реестра на одном финальном коммите; она нужна перед снятием общей экспериментальной плашки. У отчёта «График контрактации» выгрузок XLSX/PDF нет и в V1 (кнопки V1 отвечают 404) — это отдельная новая функция, решение о ней не принято. Вопрос отправки адреса страницы наружу при онлайн-карте не менялся: для изменения политики нужен выбор пользователя.

Повторная приёмка ключевых рабочих мест после `c913ac7` (все записи — на отдельных копиях обезличенной БД): АРМ комплектовщика `scripts/audit_work/chk_picker.mjs` — 18/18 (обновлено старое ожидание теста: форма показывает все выбранные строки, но до выбора контрактов к записи намечены только строки с другим статусом); МФР `scripts/audit_work/chk_mfr.mjs` — 17/17 (3D, выбор двух блоков, сброс, сроки); АРМ прораба и совместимость с V1 `scripts/verify_model_ui.mjs … foreman v1` — 16/16 (включая запись пачки, 1366×768 и чтение результата в V1). Эти прогоны усиливают приёмку, но не заменяют проверку оставшихся экранов и ролей.

Офлайн-карта: `BASEMAP_NO_INTERNET=1 … verify_basemap.mjs scenario offline-check` на тестовой копии с реальными файлами PMTiles сервера — 12 видов, 0 пустых ответов тайлов, 0 ошибок MapLibre, 0 внешних запросов, 0 смешений с OSM. На региональных и детальных видах Москва/Тула/Казань и на границе двух файлов сетка 5×5 закрыта. На обзорном z3 пять ячеек нижней строки сетки находятся вне покрытия нарисованной подложки; это ограничение географии файла, а не пустые тайлы/сбой браузера. Онлайн-режим и политика передачи адреса вовне в этом проходе не менялись и не проверялись.

## Повторная приёмка на финальном коде (2026-09-23)

Все проверки ниже выполнялись на отдельных копиях `data/zhbi.anon.db`, кроме чисто клиентских тестов; рабочая база сервера 8000 не изменялась.

- Автоматический обход 75 видимых экранов со статусом 5 на настоящем backend: **87 PASS / 0 FAIL**. Проверяется монтирование, отсутствие исключений JavaScript и ответов 5xx; для четырёх рабочих мест и карты — также отсутствие прокрутки страницы при 1920×1080 и 1366×768. Скрипт `scripts/audit_work/check_all_routes.mjs`. Это проверка доступности, а не всех действий записи каждого экрана.
- Администрирование: браузерный полный прогон `scripts/verify_admin_ui.mjs` — **243/243**, HTTP/права/конкуренция `scripts/verify_admin_backend.py` — **290/290**. Тест входа «от имени» актуализирован под переключение этой же вкладки; проверены личность по `/me`, полоса и возврат администратора.
- Отчёты V1/V2: `scripts/audit_work/chk_reports.mjs` — **31/31**, права отчётов — **22/22**; справочник — **32/32**; комплектовщик — **18/18**; МФР — **17/17**. `scripts/verify_element_rows.py` нарушений не нашёл; десять раундов конкурентной контрактации `scripts/verify_contract_guard_concurrency.py` прошли без переполнения остатка и двойной записи.
- Самопроверки API и имитации backend теперь запускаются с настоящим `api.js` в Node. Тестовая подмена только `write-gate.js` ограничена ESM-загрузчиком из `scripts/v2_tests/allow-all-loader.mjs` и не попадает в код, отдаваемый браузеру. Исправлена слишком короткая очередь временного HTTP-сервера тестов: при параллельной загрузке модулей она вызывала `ERR_CONNECTION_RESET` и ложные провалы.
- Браузерный стенд рабочих мест `WS-*`: **16 PASS / 0 FAIL** после актуализации ожиданий к скрываемой левой панели, новой вкладке «Статус» и командам получения данных мини-отчёта. Эти проверки оболочки дополняют живую проверку геометрии выше.

Для снятия общей экспериментальной плашки эти результаты ещё **недостаточны**: обход маршрутов не проверяет каждую запись и каждую роль; требуются итоговая сверка V1/V2 по оставшимся операциям и полная актуализация старого браузерного стенда (часть его GT-сценариев всё ещё проверяет прежний режим ограниченного выпуска, когда уже работающие операции были отключены). Нельзя превращать устаревшие ожидания теста в «зелёный» результат простым пропуском сценариев. По этой причине плашка пока остаётся.

Дополнительная проверка тяжёлого МФР-объекта 3 (30 078 Revit-элементов, но 0 блоков) выявила реальную ошибку видимости: штатный слой «Блоки» был включён, а «Элементы» — выключен, поэтому в 2D показывался пустой SVG при ненулевом счётчике. Теперь при первой загрузке объекта без геометрии блоков автоматически включается слой элементов; после ручного переключения он не включается повторно. Объект 3 прошёл **5/5** (видимость, ручное отключение, отсутствие прокрутки), контрольный объект 4 — **3/3**, повторная регрессия МФР (3D, сроки, фильтры) — **17/17**. Диагностика в `check_all_routes.mjs` отличает «SVG создан» от «схема загрузилась и видна».

Старый стенд `shell,ua,a11y,lc,ap,rd,bw` не является сейчас приёмочным: 115/119 его строк упали до проверки действий из-за устаревшей структуры навигации и стартовой страницы. Замена только имени CSS-класса снизила число падений, но не устранила устаревший сценарий (при отдельном прогоне `shell,ua` — 61/68 строк упали). Эти результаты не противоречат живому прогону `verify_admin_ui.mjs` 243/243 на настоящем backend, но показывают необходимость переписать стенд под V2, не маскируя падения. Экспериментальная плашка остаётся до этой сверки.
