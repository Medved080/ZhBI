## 1. Что перенесено (по операциям V1 → V2)

Права: «Секции, этажи и блоки объекта» — раздел `blocks` (заводская матрица: «Изменение» только у роли `admin` на объекте,
роли `view`/`user` — только чтение; ЭТО ДРУГОЙ раздел, чем `work_progress` у остального экрана «Учёт по блокам» — обе роли
`user2`(user)/`user4`(view) в проверках получают 403 на структуру, хотя `user2` в других частях mfr имеет запись по
`work_progress`). Загрузка справочника видов работ и правка ячейки отчёта — раздел `work_progress` (та же матрица, что у
ЗР/факта). В шлюзе — отдельная строка на каждую операцию (блок `// -- Секции, этажи, блоки… (mfr2)` в
`app/static/v2/write-gate.js`).

| Операция V2 | Запрос | Строка шлюза | Что гарантирует |
| --- | --- | --- | --- |
| Секция: добавить | `POST /objects/{o}/sections` `{code, name}` | `section.create` | код обязателен, дубль — отказ сервера |
| Секция: переименовать | `PATCH /objects/{o}/sections/{s}` `{name, axis_from, axis_to}` | `section.rename` | привязка к осям в V2 НЕ редактируется — форма пересылает её как есть (иначе PATCH стёр бы уже заданную) |
| Секция: удалить | `DELETE /objects/{o}/sections/{s}[?force=true]` | `section.delete` | неиспользуемая — сразу; занятая — 409 с точными числами (что удалится каскадом / что потеряет привязку), подтверждение → повтор с `force=true` |
| Этаж: добавить | `POST /objects/{o}/levels` `{kind, floor, name, elevation_mm, section_codes}` | `level.create` | дубль ключа — отказ |
| Этаж: правка | `PATCH /objects/{o}/levels/{l}` `{name?, elevation_mm?, height_mm?}` | `level.edit` | частичная правка |
| Этаж: удалить | `DELETE /objects/{o}/levels/{l}[?force=true]` | `level.delete` | тот же план последствий, что у секции |
| Блок: создать | `POST /objects/{o}/blocks` `{section_id, level_id}` | `block.create` | клетка матрицы; повтор — та же запись (идемпотентно) |
| Блок: удалить | `DELETE /objects/{o}/blocks/{b}[?force=true]` | `block.delete` | план последствий: ЗР со сроками и фактом, записи статусов |
| «Обновить принадлежность» | `POST /objects/{o}/blocks/recalc-membership` | `block.recalc` | пересчёт секции/этажа элементов модели по геометрии блоков |
| Геометрия блока | `PUT /objects/{o}/blocks/{b}/boxes` `{boxes:[{x0,x1,y0,y1}]}` | `block.boxes` | полный набор разом (как V1); предупреждение о пересечении с соседней секцией не блокирует сохранение |
| Виды работ: сверка xlsx | `POST /objects/{o}/work-types/analyze` (файл) | `worktypes.analyze` | ничего не пишет |
| Виды работ: применение | `POST /objects/{o}/work-types/apply` `{token}` | `worktypes.apply` | добавит/вернёт списанные/спишет пропавшие (`retired_at`, история не теряется) — ручного добавления ОДНОЙ строки в V1 нет, весь каталог правится файлом целиком |
| Отчёт «статусы»: ячейка блока | `PUT /objects/{o}/blocks/{b}/work-progress-cell` `{work_type_id, percent, report_date}` | `block-progress-cell` | процент 0..100, попадает в тот же документ факта на дату, что «Факт» в панели блока |
| Отчёт «статусы»: ячейка секции/объекта | `PUT /objects/{o}/work-progress/cell` `{work_type_id, block_id:null, section_id, status}` | `work-progress.cell` | клик крутит План → В работе → Выполнено → План |

Печать и выгрузка (без строк шлюза — не изменяющие операции):
* **Отчёт «Учёт по блокам: статусы»** — кнопка «Печать» (окно печати браузера, `app/static/v2/print.js`, общий узел для
  всех отчётов V2).
* **Плоская шахматка → «Бланк обхода (печать/выгрузка)»** — окно: формат A4/A3, охват (всё здание/диапазон этажей),
  предпросмотр по листам (лист — своя группа секций по ширине бумаги, как в V1), «Печать» (окно печати браузера),
  «Сохранить в PDF»/«Сохранить в XLSX» (тот же запрос к серверу, что в V1 — `POST …/blocks/chess-flat-export.pdf|.xlsx`,
  уже был в белом списке `api.download`, новых строк шлюза не потребовалось).

Экраны: вкладка «Блоки» экрана `#/blocks` (`app/static/v2/mfr-structure.js`, заменила прежний read-only список — секции,
этажи, матрица блоков, геометрия), вкладка «Виды работ» того же экрана (`blocks-screen.js`, добавлена загрузка xlsx),
`#/report-block-status` (`app/static/v2/reports.js`, `read-screen.js` — правка ячейки, кнопка «Печать»), `#/chess-flat`
(`app/static/v2/chess-flat-screen.js` — окно «Бланк обхода»).

## 2. Упрощения относительно V1 (сознательные, ради контроля объёма)

* **Геометрия блока** — редактирование числовыми полями (x0/x1/y0/y1) с живым SVG-предпросмотром (свой блок — акцентным
  цветом, соседи по этажу — серым, как в V1); перетаскивание мышью (drag за угол/ребро/целиком) НЕ перенесено — тот же
  результат (набор прямоугольников, полный набор пишется разом), но без жеста. Подложка — картинка плана этажа из PDF —
  тоже не перенесена (декоративная опция V1, не часть базовой возможности «редактирование геометрии»).
* **Печать бланка обхода** — разбивка строк ВНУТРИ листа по физическим страницам делается браузером (`break-inside:
  avoid`, повтор заголовка таблицы через `thead{display:table-header-group}`), а не измерением пикселей в скрытом узле,
  как в V1 (`measureLevelsFit`). Разбивка ПО СЕКЦИЯМ (лист = группа секций по ширине бумаги) перенесена как есть — только
  она влияет на состав PDF/XLSX-выгрузки, которую считает сервер. Диапазон печати (интерактивный листатель с превью
  текущего листа) заменён списком всех листов в одном скролле.

## 3. Серверный дефект — найден и исправлен (воспроизводится и в V1, тем же кодом)

`app/work_fact.py::set_cell_percent` — правка ОДНОЙ ячейки отчёта «Учёт по блокам: статусы» (эндпоинт существовал в V1 с
2026-09-05). Строил слепок операций блока через `_percents_as_of`, который подмешивает историю МЯГКО СНЯТЫХ операций
(были в отборе, есть факт, потом сняты «Настройками» — `retired_at`, история не теряется специально), а `save_report`
следом отклонял ЛЮБОЙ слепок с операцией вне ТЕКУЩЕГО отбора (`block_settings(...)["selected"]`) — правка ОДНОЙ явно
выбранной, ТЕКУЩЕЙ ячейки падала 422 «Операции вне отбора для этого блока: […]» из-за ЧУЖИХ, давно снятых строк того же
блока. На реальных данных копии (объект 4) воспроизводится примерно на половине проверенных блоков — у них есть история
факта по операциям, которые позже сняли «Настройками». Правка: слепок строится ТОЛЬКО по операциям текущего отбора
(3 строки, `app/work_fact.py`). Проверено `scripts/verify_mfr2_ops.py` (блок с ошибкой воспроизведён, блок без истории —
чисто) и `scripts/verify_mfr2_browser.mjs` (реальный клик после починки — 200, значение в БД).
