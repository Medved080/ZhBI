## 1. Что перенесено (по операциям V1 → V2)

Права везде — раздел «Учёт по блокам» (`work_progress`): просмотр — «чтение», запись — «Изменение» (`assert_object_feature(..., "work_progress", "write")`); список блоков/секций/этажей читает раздел `blocks`. В шлюзе — отдельная строка на каждую операцию (блок `// ==== область: mfr ====` в `app/static/v2/write-gate.js`), форма тела проверяется функцией `check` (тело иной формы шлюз отклоняет).

| Операция V2 | Запрос (метод + путь) | Строка шлюза | Что гарантирует |
| --- | --- | --- | --- |
| ЗР: базовый срок | `PATCH /objects/{o}/block-works/{bw}` `{plan_start, plan_end, expected_rev}` | `block-work.plan` | отпечаток работы проверяет сервер под блокировкой записи (409 — ничего не менялось); даты — существующие, конец не раньше начала; снятая работа — 409 |
| ЗР: новая версия прогноза | то же, `{forecast_start, forecast_end, expected_rev}` | `block-work.forecast` | версия копится и не отменяется — сказано в подписи кнопки и в подтверждении; одинаковый прогноз повторно новой версии не создаёт |
| ЗР: примечание | то же, `{note, expected_rev}` | `block-work.note` | ≤ 4000 знаков |
| Групповая правка сроков (сдвиг плана/прогноза, «прогноз = план» у не начатых) | предпросмотр `POST …/block-works/bulk-preview` (чтение) → `PUT …/block-works/bulk` `{block_work_ids, op, field, days, expected}` | `block-work.bulk` | только по предпросмотру; одна транзакция; отпечатки всех работ (`expected`); сдвиг за границу дат/больше 3650 дней — 422 и откат всего |
| Состав работ блока (ЗР добавить / вернуть / снять) | предпросмотр `POST …/blocks/work-types-settings/preview` → `PUT …/blocks/{b}/work-types-settings` `{work_type_ids, expected}` | `block-settings.set` | «мягкое» снятие (есть сроки или факт — строка и история сохраняются), удаление пустой ЗР, возврат снятой; отпечаток состава |
| Состав работ ГРУППЫ блоков | `PUT …/blocks/work-types-settings` `{block_ids, work_type_ids, expected}` | `block-settings.group` | ВСЕ блоки одной транзакцией (раньше каждый блок фиксировался отдельно — при отказе на середине часть блоков менялась) |
| Факт: новый документ | `POST …/blocks/{b}/fact-reports` `{report_date, items}` | `fact.create` | процент 0..100, дата — существующая, работа — из состава блока |
| Факт: исправить документ | `PUT …/fact-reports/{r}` `{report_date, items, expected_rev}` | `fact.update` | отпечаток документа; построчная история правок («было → стало») пишет сервер |
| Факт: удалить документ | `DELETE …/fact-reports/{r}?expected_rev=…` | `fact.delete` | необратимо (каскад: строки и история); подтверждение с датой и числом работ; отпечаток |
| Шахматка: пакетный ввод факта | `POST …/blocks/chess-flat-batch` `{report_date, track_code, idempotency_key, items[{block_id, work_type_id, percent, expected_percent}]}` | `chess.batch` | окно проверки «было → станет»; одна транзакция, блокировка записи первым действием (раньше два пакета могли пройти одновременно); ключ идемпотентности; чужая правка — 409 без записи |
| Excel-правка ЗР: сверка | `POST …/block-works/bulk-edit/analyze` (файл) | `bulk-edit.analyze` | ничего не пишет (БД до/после проверена) |
| Excel-правка ЗР: применение | `POST …/block-works/bulk-edit/apply-strict` `{changes}` | `bulk-edit.apply` | «всё или ничего»; `was` сверяется под блокировкой (изменилось после сверки — 409); журнал после commit; прежний `…/apply` (по одной ЗР, «пропущено») оставлен для V1 |
| Excel: выгрузка ЗР | `POST …/block-works/bulk-edit/export` (файл) | (скачивание, `api.download`) | как V1 (пишет событие `block_bulk_export`) |

## 2. Серверные исправления (совместимые; схема БД не менялась)

* `begin_write` первым действием в писателях: PATCH ЗР, `PUT …/bulk`, `PUT` состава (одного и группы), `POST/PUT/DELETE` документов факта, `chess-flat-batch`, `PUT …/work-progress-cell`; события журнала через `activity.defer_*` — только после commit (откатившаяся пачка не оставляет событий).
* Отпечатки состояния: `rev` у ЗР (`block_works.rev_of`) и у документа факта (`work_fact.report_rev`) — необязательные `expected_rev`/`expected` в телах (V1 их не шлёт и работает как раньше); сравнение под блокировкой записи, расхождение — 409 `{conflict: true, items}`.
* `work_fact.save_block_settings(commit=False)` и групповая запись состава — одна фиксация на группу.
* Серверная проверка дат: `work_fact.is_iso_date`; PATCH ЗР (`block_ops.validate_block_work_patch`), дата документа факта, сдвиг (`block_works._shift_date`, `|days| ≤ 3650`, OverflowError → 422 с откатом).
* Новый файл `app/block_ops.py` (подключён строкой `app.include_router(block_ops_router)` рядом с `allocation_router`): два предпросмотра и строгая Excel-правка.

Контроль «до исправления» (код `feature/v2-next` на копии БД): группа блоков с несуществующим блоком отвечает 404, но БД при этом изменилась (изменено ЗР: 2) — записи не были атомарны; два одновременных PATCH одной ЗР без отпечатка оба получают 200 (последний перезаписывает первого).

## 4. Найденные и исправленные дефекты (в ходе проверки)

* Групповое сохранение состава работ не было атомарным (см. контроль выше) — исправлено.
* Два пакета шахматки могли пройти одновременно (сверка «ожидалось» шла вне блокировки) — `begin_write` первым действием.
* Окно подтверждения опасного действия: текст красной кнопки был невидим (мой стиль переопределил цвет) — исправлено.
* Журнал факта: кнопка «Сбросить» не включалась при отборе только по видам работ — исправлено.
* Шахматка: после конфликта окно проверки открывалось пустым (закрытие прежнего окна стирало новое состояние) — исправлено.
* Excel-правка: после успеха сообщение об успехе не показывалось — исправлено.
* Кнопка «Применить» групповой правки сроков не блокировалась при сдвиге за границу дат — теперь недоступна с объяснением.

## 5. Что НЕ сделано и вопросы

* Не перенесено (остаётся в V1): создание/правка/удаление секций, этажей, блоков и геометрии блоков; справочник видов работ (V2 только показывает); печать бланка обхода А4/А3 у плоской шахматки (ссылка на V1 есть); правка процента в ячейке отчёта «Учёт по блокам: статусы» (`PUT …/work-progress-cell`, серверная часть уже под `begin_write`).
* Выбор блока щелчком в 3D-режиме МФР жестом не проверен (в безголовом Chrome 3D-сцена без GPU не даёт надёжного попадания луча); в 2D (план) выбор, ⌘/Ctrl- и Shift-щелчки проверены настоящими событиями мыши. Ctrl+щелчок на macOS ОС превращает в контекстное меню, поэтому на этой машине настоящим жестом проверен ⌘+щелчок, ветка Ctrl — событием click с `ctrlKey`.
* Вопросы к пользователю: (1) переносить ли редактирование секций/этажей/блоков/геометрии (операции с предупреждением об используемых ЗР и `force`); (2) печатный бланк обхода — нужен ли в V2; (3) должна ли прежняя Excel-правка V1 (`…/apply`, частичный результат «пропущено») тоже стать «всё или ничего» (это изменение поведения V1); (4) предупреждать ли при создании второго документа факта блока на ту же дату (V1 разрешает несколько); (5) правка процента в ячейке отчёта «статусы» — в область отчётов или сюда.
