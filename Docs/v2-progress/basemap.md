## 1. Что в файлах на самом деле

Разбор — прямым чтением PMTiles/MVT (свой разборщик заголовка, каталогов и protobuf в scratchpad, без
сторонних пакетов), по ВСЕМ тайлам обоих файлов.

| | `basemap-ru.pmtiles` | `basemap-msk.pmtiles` |
|---|---|---|
| Формат | PMTiles v3, MVT, gzip, clustered | то же |
| bbox (заголовок) | 19,0–180,0 в. д., 41,0–78,0 с. ш. | 35,1–40,2 в. д., 54,2–56,9 с. ш. |
| zoom | 0–8 | 0–14 |
| Тайлов по zoom | 1/2/6/10/36/128/450/1770/6960 | 1/1/1/1/2/2/4/6/20/63/224/840/3304/12870/51027 |
| Схема | Protomaps basemap **v4** (`version` 4.15.2, planetiler 0.10.2) | то же, та же сборка |
| Данные OSM на | 2026-09-14 | 2026-09-22 (файл заменён сегодня, mtime 19:22) |

Слои (`vector_layers`): `earth`, `water`, `landcover` (z0–7), `landuse`, `roads`, `buildings` (с z11),
`boundaries`, `places`, `pois`. Свойства — `kind`, `kind_detail`, `min_zoom`, `name`, `name:ru` и ещё 40 языков,
`population_rank`, `is_tunnel`/`is_bridge`; схемы v3 (`pmap:kind`) в файлах нет. Значения `kind` —
`roads`: highway / major_road / minor_road / path / rail / ferry / aeroway / other (`kind_detail` —
motorway, trunk, primary, secondary, tertiary, residential, service…); `water`: площади water/lake/ocean и
линии river/canal/stream; `places`: country / locality (city/town/village/hamlet) / macrohood / neighbourhood.

- **Суша есть во ВСЕХ тайлах обоих файлов.** Без слоя `earth` — только тайлы открытого моря (в них есть
  `water`): ru — 2152+466+86+16+2 тайла z4–8, msk — 0. Утверждение wip-коммита «у Protomaps на низком zoom в
  части тайлов нет полигона земли» — неверно (см. §2.1: «тайл 63 КБ без earth/water» — это пустой ТАЙЛ
  MapLibre, а не файла).
- **На z0–8 тайлы двух файлов совпадают** (одна сборка, разница — пара объектов из-за разных дат OSM):
  детальный файл добавляет только z9–14 и только в своём покрытии. Покрытие на каждом zoom — прямоугольник
  из тайлов, задевающих bbox (тайлы вырезаются целиком, поэтому данные есть и чуть за bbox).
- **Обзорный файл за z8 не детализируется**: на z8 у Москвы — только highway/major_road (trunk, primary),
  города и посёлки, крупные массивы landuse; зданий (с z11) и улиц в нём нет вовсе. Дальше z8 MapLibre
  растягивает тайлы z8. Это предел данных, цветом его не восстановить.

Ответы `Range` сервера (проверка скриптом из scratchpad на стенде, по 4 диапазона на файл, включая хвост и
выход за конец):
все `206`, `Content-Range` точный (`bytes 0-16383/297575296`…), тело побайтно совпадает с файлом, выход за
конец усечён правильно; `ETag` сильный (`md5(mtime-size)` Starlette), `Accept-Ranges: bytes`. В браузере — 34–80
запросов диапазонов на прогон, ни одного не-206.

## 2. Причина (доказано на стенде)

Картинка со скриншота («подробная карта рядом с бежевым прямоугольником, внутри подписи и отдельные дороги»)
складывается из трёх независимых дефектов (§2.1–2.3), главный — первый; четвёртый (§2.4, кэш) к картинке
не относится, но подтвердился и исправлен.

### 2.1. Тайлы пустели ЦЕЛИКОМ из-за отсутствующих глифов

Вендорены глифы Noto Sans только двух диапазонов — 0-255 и 1024-1279. Слой подписей брал `name`, а в
названиях OSM встречаются символы вне них. MapLibre запрашивает недостающий диапазон, сервер отвечает 404,
воркер роняет разбор ВСЕГО тайла, а главный поток, увидев ошибку со `status 404`, считает, что «тайла нет»
(`VectorTileSource.loadTile`: `if (t && 404 !== t.status) throw t; this._afterTileLoadWorkerResponse(e, null)`)
и рисует тайл пустым: без суши, воды, дорог — и без события `error`, поэтому в консоли тихо.

Доказательства:
- Перехват `Actor.sendAsync` (итог каждой загрузки тайла в воркере) на исходной версии, вид z6 у Москвы:
  `LT basemap1 6/37/20 ERR AJAXError: Not Found (404): /static/vendor/glyphs/Noto Sans Regular/256-511.pbf`,
  то же для 6/37/19, 4/9/5, 4/8/4…, `6/38/21 … 8192-8447.pbf`. При этом протокол pmtiles отдал эти тайлы
  полностью (118 618, 107 497, 61 568 байт), а в файле у них есть `earth` и `water`. «Тайл 63 КБ без
  earth/water» из wip-коммита — это 6/38/21 (61 568 байт) после такой ошибки.
- Виновники по файлам (сканирование всех подписей `places`): в обзорном из-за `name` пустеет 193 из 6960
  тайлов z8, 82 из 1770 z7, 22 из 450 z6 (и по нескольку на z1–5); в детальном — 45 тайлов z12–14 ВНУТРИ
  Московской области. Символы: `ș š ă ł ė ž č` (латиница с диакритикой, 256-767), грузинский, греческий, `’`
  (U+2019) и `–` (U+2013) — диапазон 8192-8447, `№` (U+2116) — 8448-8703. У Москвы: столбец тайлов западнее
  33,75° в. д. на z6 («Rēzekne»), тайл южнее 52,48° с. ш. («Куп’янськ»), на z7 — полоса тайлов вдоль границы
  с Украиной и Латвией; в области на z12 — четыре тайла у 55,33–55,43/37,44–37,62 («СНТ №8»), «КП
  Сараево–Москва», «микрорайон №2» и т. д.
- Исправление устраняет все пустые тайлы (таблица §4: 0 пустых во всех сценариях итоговой версии, те же
  тайлы 6/37/19, 6/37/20, 6/38/21, 12/2474/1287 строятся с данными).

### 2.2. Смешение интернет-карты и файлов

`стильКарты()` при включённой «Карте из интернета» клал растр OSM ПОД непрозрачные слои файлов. Где тайл файла
разобрался, он закрывал интернет-карту упрощённым стилем; где опустел (§2.1) — сквозь дыру была видна
подробная карта OSM. Граница «прямоугольника» = граница тайлов, опустевших из-за глифов. Гипотеза
пользователя («успешно загруженный офлайн-тайл перекрывает онлайн-подложку упрощённым стилем») верна
наполовину: перекрытие есть, но форма прямоугольника задаётся не покрытием, а тайлами, тихо опустевшими из-за
§2.1. Бежевый — цвет суши wip-версии (`#f3ede0`; в исходной `#f5f5f0`), «отдельные дороги» — обзорный файл z8,
растянутый на крупный масштаб.

### 2.3. Обзорный файл рисовался ПОВЕРХ детального

Слои шли в порядке имён файлов: `basemap-msk` → `basemap0`, `basemap-ru` → `basemap1`, то есть обзорный
выше. Его непрозрачная суша закрывала детальный файл на всех масштабах: в Москве на z12–15 сверху был
растянутый z8 (сетка проб §4: «ru» во всех 25 точках у исходной и wip-версии). Wip убрал у детального сушу,
но оставил обзорный сверху — детали по-прежнему не видны.

### 2.4. Кэш: замена файла под тем же адресом

`GET /map/tiles/{name}` отдавал `Cache-Control: public, max-age=604800` по адресу без версии. Проверка
(scratchpad `cachetest.mjs`, ссылка `basemap-swap.pmtiles` сначала на ru, затем на msk, тот же браузер):
после замены `/map/config` уже говорит «297 МБ, max_zoom 14, bbox 35,1…40,2», а все 19 запросов диапазонов
при двух следующих открытиях идут из HTTP-кэша (`transferSize 0`) со СТАРЫМ ETag; источник MapLibre остаётся
`maxzoom 8`, границы старого файла, на z10 — тайлы z8. Проверка ETag в `pmtiles.js` не срабатывает: несовпадения
нет, раз всё пришло из кэша согласованно. Новый файл не виден до истечения недели. Chrome и Edge на Windows не
затронуты: `pmtiles.js` у них (`chromeWindowsNoCache`) ходит с `cache: "no-store"` — зато и без кэша вовсе.

## 3. Что изменено

`app/static/map.js` (общий для V1 и V2):
- **Явные режимы**: «С сервера» (только векторные файлы, ни одного внешнего запроса) и «Из интернета» (только
  растр OSM). По умолчанию — по настройке администратора (`/map/config.online`); если доступны оба —
  переключатель «Подложка: С сервера / Из интернета» в левом верхнем углу КАЖДОЙ интерактивной карты
  (`aria-pressed` у активного), выбор — `localStorage["zhbi.map.basemap"]`, общий для V1/V2. Без автоматики:
  пропал интернет — в переключателе «нет связи», режим тот же. Переключение снимает/кладёт только слои
  `подложка-*` под первый слой объектов — точки, кластеры, всплывашка, отбор не пересоздаются.
- **Глифы через протокол `zhbi-glyphs://`**: вендоренный диапазон — файл, прочие — пустой набор глифов
  (тайл цел, пропадает только символ). Подписи — `name:ru`, иначе `name`.
- **Правило нескольких файлов** (`порядокФайлов()`): снизу вверх по `max_zoom`; файл включается с zoom
  «`max_zoom` пересекающихся нижних + 1» (msk — с 9), его суша и вода непрозрачны и закрывают нижний в своём
  покрытии, за покрытием остаётся нижний; подписи нижнего внутри bbox верхнего на его уровнях отключены
  (`within`). Проверено по результату, а не по площади bbox (§4, §5): в покрытии сверху msk, за ним ru, дублей
  подписей нет (пробы на z8–12 у границ).
- **Офлайн-стиль по схеме v4**: суша, landcover/landuse по `kind` (лес, зелень, поля, жильё, промзоны,
  соцобъекты, пески, ледники, болота), вода (площади и реки), границы стран и регионов, дороги по классам с
  обводкой (магистрали, trunk/primary, secondary/tertiary с z9, улицы с z12, дорожки с z15, ж/д с z9 без
  метро, тоннели полупрозрачно), здания с z13, населённые пункты по `population_rank`/`min_zoom`
  (`symbol-sort-key`, крупные — Bold). Шрифты — только вендоренные Noto Sans Regular/Bold.
- Решение wip пересмотрено: **фон = цвет суши снят** (он прятал пустые тайлы, не возвращая воду и дороги);
  фон снова холодный (`#e3e6ea`) и виден только там, где данных нет. **Выбор «базового» файла по площади bbox
  снят** — заменён правилом выше.

`app/project_map.py`:

## 6. Ограничения, которые кодом не закрыть

- **Обзорный файл за z8** — только крупные дороги, города, крупное землепользование; зданий и улиц нет. Вне
  детальных вырезок (Казань и т. п.) крупнее z8 карта грубая. Нужна детальность — ещё одна вырезка
  (`scripts/fetch_map_tiles.py --bbox … --maxzoom 14 --name …`), правило совмещения подхватит её само.
- **Граница детального покрытия видна** как ступень детальности по линии тайлов (например, у Тулы по 54,2°
  с. ш. на z9+): за ней данных детального файла нет. Это граница данных, а не наложение стилей.
- **Символы вне вендоренных глифов** (`№`, `–`, `’`, латиница с диакритикой, грузинский, греческий) в подписях
  пропадают: «СНТ 8» вместо «СНТ №8». Порядка 1 % подписей. Полное решение — вендорить ещё диапазоны Noto
  Sans (8192-8447, 8448-8703, 256-767…) — только с подтверждения пользователя (правило проекта).
- Названий улиц, водоёмов и POI в стиле нет (в данных есть) — в задание не входили.
- **Интернет-карта и Referer.** Приложение отдаёт `Referrer-Policy: same-origin`, поэтому браузер не посылает
  `tile.openstreetmap.org` адрес страницы, а политика OSM его требует: сервис может отвечать картинкой «Access
  blocked» (HTTP 200, заголовок `X-Blocked: Access denied…`). На стенде так было в одном прогоне из трёх (все
  362 тайла), в двух других — нормальные тайлы; `curl` без Referer — всегда «blocked», с Referer — карта.
  Обходить политику не стал (запрет ослабления защит) — вопрос пользователю.

## 7. Открытые вопросы пользователю

1. Разрешить ли браузеру сообщать адрес сервиса OSM (например, `referrerPolicy: "strict-origin"` только для
   запросов тайлов из интернета через свой протокол — остальная политика не меняется)? Без этого режим «Из
   интернета» может в любой момент показать «Access blocked».
2. Вендорить ли дополнительные диапазоны глифов Noto Sans (≈ +100–300 КБ), чтобы «№», «–», «’» и диакритика в

   Нужно ли наоборот (файлы по умолчанию, интернет — по выбору)?
