# Бот eXpress: опрос численности по расписанию (2026-10-23)

Ветка `claude/express-bot` (worktree `.claude/worktrees/express-bot`), в `main` не влита. Продолжение `Docs/headcount.md` §7 («Второй этап: бот»):
вместо Telegram — корпоративный мессенджер eXpress.

## 1. Что делает

По расписанию бот пишет выбранному контакту в eXpress: «Объект …, нужна численность за такой-то день». Контакт отвечает кнопками
(подрядчик → вид работ → рабочие → ИТР → механизаторы), каждая строка сразу попадает в `headcount_records` с источником `bot` и историей
(`headcount_history`). Контакт — физлицо из справочника или произвольный человек. Дальше по расписанию — напоминание тем, кто не ответил,
и сводка выбранному адресату. Разделы запроса расширяемы (`express_schedules.section`), сейчас только `headcount`.

Миграция аддитивна: таблицы создаются при старте (`CREATE TABLE IF NOT EXISTS`), существующие данные не затрагиваются.

## 3. Инварианты

- **Ключ бота не в БД.** Файл `<база>.express-secrets.json` (0600) — не попадает в копии и в тестовый стенд. Перенос боевой базы на тестовый сервер
  с включённым `enabled` писать от имени бота не позволит: ключа там нет.
- **Входящее защищено подписью.** `/command`, `/status`, `/notification/callback` без верного JWT (HS256 ключом бота, `iss`/`aud` = бот) дают 401, тело не читается.
  Маршруты открыты без сессии пользователя — иначе CTS не достучится.
- **Контакт без прав в системе.** Он вносит численность только по объекту и за день своего запроса — это записано в запросе. Чужой номер запроса в кнопке отклоняется.
  Незнакомый отправитель получает отказ, а его логин и huid видны в журнале обмена (по ним заводят контакт).
- **Без дублей и без лавины.** Пара (расписание, день) уникальна. Срабатывание догоняется только в окне 1 час после времени (сводка — 3 часа);
  моменты раньше `effective_from` (создание, правка времени/дней/включения) не догоняются.
- **Каждая строка пишется сразу**, а не пакетом: брошенный диалог не теряет внесённое. Повторный ввод ключа заменяет число (как в форме), прежнее — в истории.
- **Выключенный бот молчит**: расписание не срабатывает, входящие игнорируются.

## 4. Подключение (тест → бой)

1. Зарегистрировать бота в eXpress (администратор CTS): адрес бота — `http://pm-test.mcy-1.ru:8011` (позже `http://pm.mcy-1.ru:8011`), имя `pm_bot`.
   CTS сам обращается на `{адрес}/command`, `/status`, `/notification/callback` — нужна сетевая доступность сервиса со стороны CTS (внутренний контур).
2. В «Администрирование → Бот eXpress → Подключение» (V1 и V2; администратор сервиса, раздел `express_admin`): адрес CTS, UUID бота, имя, ключ; «Проверить связь» (бот получает токен, ничего не отправляется); включить.
3. Контакты: добавить физлицо или произвольного человека, указать e-mail и/или доменный логин. Каждый контакт один раз открывает бота и шлёт `/start` — так бот узнаёт личный чат.
   «Найти в eXpress» по e-mail запоминает идентификатор заранее.
   **Внешние люди** (нет доменного логина и e-mail в eXpress): кнопка «Код привязки» в карточке контакта выдаёт одноразовый код (8 знаков без I, O, 0, 1,
   действует 24 ч, показывается один раз, в БД только sha256). Человек отправляет боту `/start КОД` (неизвестному можно и просто код) — бот запоминает его
   аккаунт и личный чат. Неверный код: 5 попыток с аккаунта за 10 минут, затем блокировка на 10 минут. Аккаунт, уже привязанный к другому контакту, второй код
   не принимает; новый код перепривязывает контакт к другому аккаунту. Поле «Телефон» справочное (позвонить, передать код): BotX телефон боту не присылает,
   по нему контакт не опознаётся.
4. Расписания — на объекте: дни, время (МСК), за какой день, напоминание, сводка, кому.
Для боя регистрируется отдельный бот на `pm.mcy-1.ru:8011` — подключение и ключ вносятся там заново (в базе и файле секретов сервера).

## 4а. Строки и ответственные (2026-10-26)

- **Контакт — только из справочника физлиц.** Имя берётся из справочника, один контакт на физлицо; прежние контакты без физлица помечены «не из справочника»
  и требуют выбора физлица при правке. Удаление физлица с заменой переводит на замену и контакт бота, и ответственность (`app/dict_delete.py`).
- **Ответственный за строку «подрядчик + вид работ».** Таблица `headcount_contractor_works` (подрядчик объекта, вид работ кодификатора, ответственный — физлицо).
  Ведётся на закладке «Численность → Подрядчики» (кнопка «Виды работ» у подрядчика: добавить вид работ, назначить или снять ответственного). Перечень не ограничивает
  ввод численности в форме — это привязка людей к строкам.
- **Диалог бота** показывает контакту только строки, где ответственным указано его физлицо (`headcount.responsible_rows`): список кнопок (✓ у внесённых), по нажатию — вопросы
  рабочие → ИТР → механизаторы. Выбора подрядчика и поиска вида работ нет. Итоги в меню и при закрытии — по строкам контакта; запись проверяет, что строка за ним ещё закреплена.
- **Нет строк — не спрашиваем.** Планировщик заводит запрос закрытым с причиной (повторных обходов нет), «Спросить сейчас» отвечает 400 с подсказкой. Сводка администратору
  в этом случае говорит, что опрос не проводился.

## 5а. Авторизация BotX API: две схемы (выяснено на первом подключении, 2026-10-23)

CTS `exp.mcy-1.ru` выдавал токен по `GET /api/v2/botx/bots/{id}/token` (схема v1), но на любой вызов BotX API с ним отвечал 401 `unauthorized`
(сверка по curl с ВМ). Пример администраторов на pybotx работает по схеме **v2**: бот сам строит JWT на каждый вызов (HS256 ключом бота,
`iss` = id бота, `aud` = имя хоста CTS без схемы и порта, `exp` = +60 с, `nbf`, `iat`, `jti`, `version` = 2), `Authorization: Bearer <jwt>`. Клиент
(`app/express_bot.py`, `_authorized_call`) пробует v2, при 401 — v1, запоминает сработавшую схему. «Проверить связь» делает настоящий безвредный
вызов (`GET /api/v3/botx/chats/list`), а не только запрашивает токен: «токен выдан» ничего не доказывало. Проверка — `scripts/verify_express_bot.py`
(макет CTS принимает обе схемы, только v2, только v1 или ничего).

## 6. Не проверено на настоящем CTS (сверено только с исходниками pybotx)

- Ответ `users/by_email` (поле `user_huid`/`huid`) и ошибка `chat_not_found` для контакта, который боту не писал.
- Формат входящей команды и кнопок (`command.data` приходит боту как есть) — по pybotx; проверить на живом CTS.
- Бот пока не умеет сам открыть личный чат: контакту нужно написать `/start`. Если в вашем CTS есть способ создать личный чат по huid — добавить в `express_bot`.
- Протокол бота (версия) выбирается в админке eXpress; `/status` возвращает список команд `/start` и `/help`.

## 7. Открыто

- Праздники не учитываются (как и в сроке численности); суббота/воскресенье — выбором дней и смещением «за вчера».
- Редактирование и удаление строк через бота не предусмотрено (только замена числа повторным вводом); удаление — в форме.
- Вкладка «Ввод численности» открытого окна не обновляется сама, когда бот внёс данные (общее поведение экрана: данные дня грузятся один раз).
- Запись в «Что нового» — текст согласовать с пользователем.
- Обучающий блок (`scripts/check_training_coverage.py` предупреждает о двух новых разделах прав).
