Цвет по статусу

Проекты

Проект — группа объектов, как правило соседних зданий одной площадки. Собственных данных у проекта нет, кроме реквизитов: все свойства, справочники и контракты живут внутри объекта. Сроки СМР не задаются, а сводятся из сроков подчинённых объектов — поэтому не могут с ними разойтись.

Объекты

Объект — здание или стройплощадка. Элементы принадлежат объекту, а не файлу чертежа: новая версия чертежа обновляет их, сохраняя статусы и историю.

Чертёж загружается отдельно — «Обмен данными → Загрузить чертёж».

Заполнить пустые «Объект» и «Проект»

Временная обработка. Иерархия «Проект → Объект» вводилась поэтапно, и часть записей заведена до появления у них этого поля. Запись без объекта не видна ни в одном справочнике объекта и доступна только администратору сервиса. Когда таких записей не останется, обработку следует убрать: новые записи без объекта система заводить не даёт.

Внешний вид

Настройка личная: сохраняется за вами и переезжает вместе с вами на другой компьютер. На данные и на других пользователей не влияет.

Подъём — угол над горизонтом: 90° — взгляд строго сверху, вид плана; меньше — вид сбоку. Поворот отсчитывается от вида, где числовые оси стоят вертикально, а буквенные горизонтально; положительный угол поворачивает камеру по часовой стрелке, отрицательный — против. По умолчанию 30° и −30°. Настройка личная; применяется при переходе в 3D и по кнопке сброса вида.

Подпись, которая на текущем масштабе получается мельче этого числа пикселей, не рисуется вовсе — и на схеме, и в 3D: прочитать её всё равно нельзя, а тысячи таких подложек закрывают чертёж и стоят кадра. Меньше значение — подписи появляются раньше и работа идёт медленнее; больше — схема быстрее, подписи видны только вблизи. По умолчанию 12. Настройка личная.

Настройка этого компьютера: хранится в браузере и не меняется у других пользователей.

Сменить пароль

Ваш пароль задан администратором — значит, его знает не только вы. Задайте свой, чтобы продолжить работу.

Пользователи

Права пользователей

Роль выдаётся на уровень: «Все проекты» действует на всё, роль проекта перекрывает её внутри проекта, роль объекта — внутри объекта. Пустая ячейка значит «не задано»: действует роль сверху, она подписана серым. Администратор сервиса видит и правит всё в обход выданных прав — его строка показана, но не редактируется.

Настройка ролей

По вертикали — разделы системы, по горизонтали — роли, в ячейке объём доступа. Роли НЕЗАВИСИМЫ: одна не включает другую, человеку можно выдать несколько на одном объекте, и разрешения складываются — действует наибольшее из выданного. Общесервисные разделы (контрагенты, пользователи, копии) проверяются не на показываемом объекте, а на любом доступном. Администратор сервиса проходит все проверки в обход, снять это нельзя — запереть систему настройкой не получится.

Новая роль заводится пустой — права отмечаются в её колонке.

Доменная авторизация

Пользователь вводит на обычной форме входа свой доменный логин и доменный пароль, сервис проверяет пару у контроллера домена (LDAP-bind). Служебная учётная запись не нужна — сервис не хранит доменных паролей. Кому именно входить по домену, задаётся в карточке каждого пользователя («Администрирование → Пользователи → Способ входа»); из домена никто автоматически не заводится.

На место {login} подставляется доменное имя пользователя из его карточки. Обычные варианты: {login}@corp.local либо CORP\{login} — какой принят в вашем домене, знает его администратор.

Нужен только поиску по каталогу в карточке пользователя; на вход не влияет. Пусто — сервис спросит корень у самого контроллера домена, это обычно и есть верный ответ.

Пробная привязка с полями, введёнными выше (сохранять для этого не нужно). Проверяйте своей доменной учётной записью — ни логин, ни пароль не сохраняются.

Критическая операция: замена всей базы
Загрузка снимка стирает базу этого сервера целиком и ставит на её место содержимое другого сервера: все изделия, вся история статусов, все контракты, все пользователи и пароли, настройки и вложения. Не дополняет — замещает. Текущие данные этого сервера после замены останутся только в служебной резервной копии. Раздел существует ровно для одного: привезти боевые данные на тестовый или девелоперский сервер, чтобы работать на реальном объёме. На боевом сервере загружать снимок нельзя.
1Выгрузить снимок (на сервере-источнике)
Архив .zip: файл базы целиком и папка вложений. Ничего не меняет — это выгрузка.
2Сверить снимок (на сервере-приёмнике)
Покажет, что приедет и что будет потеряно. Ничего ещё не меняет.
3Заменить базу
Доступно после сверки. Перед заменой сервис сам снимет резервную копию текущей базы.

Выгрузите снимок реквизитов всех элементов всех объектов, поправьте в Excel и загрузите обратно. Система покажет расхождения — применится только то, что вы отметите флажками. История статусов в этот файл не входит — для неё переключитесь в режим «История статусов».

Лист «История статусов» — строка на каждую запись истории: статус, момент установки, кто изменил, комментарий. Правятся четыре колонки: «Статус», «Дата и время установки», «Кто изменил», «Комментарий». Строка с пустым «№ записи» и заполненным UID элемента — новая запись. Удалить запись файлом нельзя (это делается в карточке элемента), пустая ячейка означает «не трогать». Порядок статусов проверяется: если дата более позднего статуса раньше предыдущего, строка отклоняется и не грузится. Другие записи система сама не меняет — применяется ровно то, что вы отметили.

Лист «Контрактация» — реестр: строка на каждую позицию контракта, а рядом в той же строке реквизиты её владельцев — контракта, спецификации, договора и контрагента. Правится всё, кроме наименования контракта: оно генерируется из самой этой цепочки. Строка с пустым «№ позиции» и заполненным «№ контракта» — новая позиция этого контракта (так же, как в отдельном инструменте «Импорт контрактации из XLS»); новые контракты, спецификации, договоры и контрагенты этим файлом не заводятся — для них есть тот самый импорт. Удалить позицию файлом нельзя (это делается в форме контракта), пустая ячейка означает «не трогать». Один документ повторяется в файле десятки раз: если строки задают одной спецификации, договору или контрагенту РАЗНЫЕ значения, применить нельзя ни одно — такие строки отклоняются.

Импорт истории статусов из XLS

Запись «Запланирован», созданную импортом чертежа, импорт сам сдвинет раньше самого раннего события элемента — иначе проставленная задним числом дата поставки/монтажа оказалась бы раньше неё и статус откатился бы в «Запланирован».

Восстановление статусов из выгрузки

Для случая, когда история статусов элементов была потеряна (например, после аварийной пересборки БД) — принимает файл выгрузки "Статус на дату" (Действия → Обмен данными → Экспорт в XLS) или "История статусов". Для КАЖДОГО элемента, найденного в файле, история пересоздаётся заново по нему (режим "Заменить") — обычное "Дополнить" здесь не сработает: у только что пересозданных импортом чертежа элементов уже есть свежая запись "Запланирован" с сегодняшней датой, она новее восстанавливаемых дат и "победит" как последняя.

Резервные копии базы данных

Копия содержит всю базу целиком: элементы и историю их статусов, пользователей, контрагентов, договоры, спецификации и контракты с позициями, зоны, все справочники, настройки и журнал действий. Выборочного экспорта нет — теряться нечему. Копии хранятся на диске сервера, в папке data/backups/ рядом с самой базой. Восстановление всегда начинается с автоматической служебной копии текущего состояния — если выбрана не та точка, вернуться будет куда.

Виды работ: темп и порядок

Поток: очередь фронтов крана

Считает даты по исходным данным и количествам из модели: длительность работы = количество / темп, фронты идут в порядке потока встык, краны работают параллельно, календарь семидневный. Результат сохраняется новой версией прогноза.
